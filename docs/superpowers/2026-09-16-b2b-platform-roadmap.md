# Tesseract как платформа: организации, курсы, задания, Прометей — разбор и план

**Дата:** 2026-09-16, вторая редакция 2026-09-17
**Статус:** дорожная карта. Каждый цикл перед реализацией получает свою спецификацию
в `docs/superpowers/specs/` и план в `docs/superpowers/plans/`.
**Основание:** ветка `instrument-ui` выложена на боевой. Продукт делится на B2C
(то, что есть) и B2B (организации, курсы, задания).

**Что изменилось во второй редакции:**
- добавлен цикл эксплуатации: без него «много пользователей» упрётся в очередь из двух
  генераций в памяти одного процесса;
- найдена мина во входе: лимит неудач по IP заблокирует целый класс за одним школьным NAT;
- задания в VR-лабораториях перенесены из «вне рамок» в план: химическая сцена считает
  реакцию в одной функции, мост к ней дешёвый;
- добавлен ИИ для учителя: черновик курса, вопросы по симуляции, подсказка оценки;
- исправлена схема: попытки сдачи, правка опубликованного курса, удаление людей;
- добавлены карта экранов, пилот в одной школе с метриками и вопросы законодательства РК.

## 1. Что просят

Нынешний продукт остаётся B2C и демо. Рядом появляется B2B-контур:

- **админка платформы**: организации, пользователи, использование, каталог;
- **организации** (школа, колледж, университет): учителя, группы, массовые аккаунты учеников;
- **курсы**: курс → темы → блоки (текст, тренажёр из общей или личной библиотеки,
  VR-лаборатория, задание);
- **задания**: сделать что-то в симуляции или лаборатории («смешай и получи вещество»),
  ответить на вопросы по ней, написать свой ответ;
- **учительская**: ответы, проверка, журнал;
- **персонализация**: интересы в профиле;
- **Прометей**: чат, который объясняет тему через интересы человека. Доступен всем,
  и B2C, и B2B.

Это **восемь циклов** с разной связностью:

| Цикл | Что | Для кого | Зависит от | Размер |
|---|---|---|---|---|
| 0 | Модель доступа: организации, членства, группы, вход по логину | всем | — | S–M |
| 1 | Эксплуатация под нагрузку: воркер, очередь в базе, HTTPS, бэкапы | платформе | — | L |
| 2 | Кабинет организации: учителя, группы, массовые ученики | админу организации | 0 | M |
| 3 | Курсы: конструктор для учителя, чтение для ученика | учителю, ученику | 0, 2 | L |
| 4 | Задания: выбор, текст, состояние симуляции; учительская | учителю, ученику | 3 | L |
| 5 | Задания в VR-лабораториях | учителю, ученику | 4 | M |
| 6 | Админка платформы | владельцу | 0 | M |
| 7 | Персонализация и Прометей | всем | 0 | M–L |
| 8 | ИИ для учителя | учителю | 3, 4, 7 | M |

S — до двух дней, M — до недели, L — больше недели.

## 2. На что опираемся и что мешает

**Опора:**

- **Аккаунты** (`src/lib/auth/*`): почта и пароль, `scrypt`, сессии в Postgres, проверка
  в каждом роуте. Ролей две: `admin` и `user`.
- **Симуляции** (`src/lib/storage.ts`): строго приватны, чужой id даёт 404. Для B2C так
  и остаётся; для курсов нужен второй путь доступа.
- **Кит** (`src/lib/runtime/*`): симуляция объявляет состояние через
  `SimUI.expose({ getState, reset })`, контролы видны через `SimUI.__controls()`, харнесс
  уже слушает `postMessage` от родителя. Это готовая основа для заданий «добейся
  состояния».
- **Лаборатории** (`public/labs/*`): логика в чистых модулях. В химии вся реакция
  считается одной функцией `react()` и вызывается в одном месте сцены — туда встаёт
  сообщение наружу.
- **Профиль**: `users.prefs` с белым списком ключей, `display_name`. Интересы ложатся рядом.
- **Провайдер**: роли пайплайна резолвятся в модель по имени. Роль `tutor` добавляется
  одной строкой. Стриминга нет.

**Что мешает «много пользователей»:**

| Где | Что сейчас | Что сломается |
|---|---|---|
| `src/lib/limits.ts` | очередь и реестр генераций в памяти, не больше двух одновременно | двадцать учителей перед уроком ждут по полчаса; рестарт теряет очередь |
| `src/lib/jobs.ts` | карта заданий в памяти, SSE из того же процесса | второй экземпляр приложения невозможен; в `next dev` генерация не работает |
| Генерация в веб-процессе | Chromium живёт рядом с Next | тяжёлая генерация тормозит страницы всем |
| `src/lib/auth/rate-limit.ts` | 10 неудачных входов с одного IP за 15 минут | **класс за одним NAT** вводит новые пароли с ошибками — вся школа заблокирована на 15 минут |
| Сессии | 30 дней скользящим окном | на общем школьном компьютере следующий ученик входит в чужой аккаунт |
| HTTP без TLS | сайт на голом порту | пароли учеников в открытом виде; VR не работает |
| Регистрация открыта | квота 10 генераций | бесплатный чат без лимита сожжёт ключ провайдера |

## 3. Продуктовая модель

Один аккаунт, один вход, одна навигация. Что видит человек, определяют **членства**,
а не тип аккаунта:

| Кто | Видит в навигации |
|---|---|
| Любой зарегистрированный | Создать · Библиотека · Лаборатории · **Прометей** |
| Ученик организации | **Курсы** · Лаборатории · Прометей (Создать и Библиотека — по настройке организации) |
| Учитель | всё B2C + **Преподавание** |
| Админ организации | всё учителя + **Организация** |
| Админ платформы | всё + **Админка** |

Один человек может быть учителем в двух организациях и учеником в третьей. Модель
членств делает это бесплатным. Переключатель организации появляется в меню аккаунта,
только если членств больше одного.

**Главный инвариант:** пользователь без членств не замечает изменений, кроме Прометея
и блока интересов в профиле. Это критерий приёмки каждого цикла.

### Карта экранов

```
/                         мастерская (B2C, без изменений)
/library, /labs           без изменений
/prometheus[/<id>]        беседы и беседа
/profile                  + интересы, + «вступить по коду группы»

/learn                    мои курсы (ученик)
/learn/<course>/<topic>   тема: блоки подряд, задания, «спросить Прометея»

/teach                    мои курсы (учитель)
/teach/<course>           редактор: темы слева, блоки справа
/teach/<course>/grades    журнал: ученики × задания
/teach/<course>/a/<block> ответы на одно задание, проверка
/teach/groups             мои группы

/org                      обзор организации
/org/teachers, /org/groups, /org/groups/<id>, /org/groups/<id>/credentials (печать)
/org/settings

/admin                    обзор платформы
/admin/orgs, /admin/users, /admin/catalog, /admin/usage, /admin/log
```

## 4. Модель данных

```sql
-- цикл 0
organizations  (id, slug UNIQUE, name, kind 'school'|'college'|'university',
                settings jsonb DEFAULT '{}', archived_at, created_at)
memberships    (org_id, user_id, role 'org_admin'|'teacher'|'student',
                created_at, PRIMARY KEY (org_id, user_id))
groups         (id, org_id, title, join_code UNIQUE NULL, archived_at, created_at)
group_members  (group_id, user_id, PRIMARY KEY (group_id, user_id))
group_teachers (group_id, user_id, PRIMARY KEY (group_id, user_id))
users          + login text UNIQUE NULL            -- вход без почты
               + email NULL допустим               -- у школьника почты может не быть
               + must_change_password bool DEFAULT false
               + disabled_at timestamptz NULL      -- блокировка вместо удаления
sessions       + kind 'long'|'short'               -- короткие для учеников

-- цикл 1
jobs           + kind, priority, locked_by, locked_until, attempts,
                 cancel_requested_at               -- очередь генераций в Postgres
job_events     (job_id, seq, event jsonb)          -- журнал прогресса по мере работы
workers        (id, host, seen_at, running)        -- живость воркеров
login_attempts (key, at)                           -- лимиты входа в базе, а не в памяти

-- цикл 2
invites        (token_hash PK, org_id, role, group_id NULL, created_by,
                expires_at, used_by NULL, used_at NULL)

-- цикл 3
courses        (id, org_id, owner_id, title, subject, description,
                status 'draft'|'published'|'archived', created_at, updated_at)
course_editors (course_id, user_id)                -- соавторы-учителя
course_groups  (course_id, group_id)               -- кому открыт курс
topics         (id, course_id, position, title, opens_at NULL)
blocks         (id, topic_id, position, kind 'text'|'simulation'|'lab'|'assignment',
                payload jsonb, revision int, updated_at)
topic_views    (topic_id, user_id, first_at, last_at)
simulations    + visibility 'private'|'catalog'

-- цикл 4
attempts       (id, block_id, block_revision, student_id, n,
                answer jsonb, evidence jsonb NULL, -- состояние симуляции, события лабы
                status 'draft'|'submitted'|'returned'|'graded',
                auto_score numeric NULL, score numeric NULL, comment text NULL,
                submitted_at, graded_at, graded_by)
               -- UNIQUE (block_id, student_id, n): несколько попыток, если задание разрешает

-- цикл 6
admin_actions  (id, actor_id, action, target, payload jsonb, at)

-- цикл 7
conversations  (id, user_id, context jsonb NULL, title, created_at, updated_at)
messages       (id, conversation_id, role 'user'|'assistant', content,
                tokens int, created_at)
users          + interests text[], + about text
```

**Блок — единица урока.** Тема — упорядоченный список блоков, отдельная сущность
«урок» не нужна. `payload` типизирован по `kind`:

- `text` — `{ markdown }`;
- `simulation` — `{ simulationId, caption }`: из личной библиотеки учителя или из каталога;
- `lab` — `{ slug, station?, caption }`;
- `assignment` — `{ type, prompt, stand?, attempts, dueAt?, points, ... }`, где `stand` —
  симуляция или лаборатория, на которой выполняется задание (цикл 4 и 5).

**Правка опубликованного курса.** Учитель правит курс весь год, а ответы уже сданы.
Правило: каждая правка блока увеличивает `revision`, а попытка запоминает
`block_revision`. Учительская показывает «ответ дан на прежнюю редакцию задания».
Смена правильного ответа у задания с автопроверкой предлагает «пересчитать сданные».

**Удаление.** Сейчас удаление пользователя каскадом сносит его симуляции.
В организации это недопустимо: ушедший учитель унёс бы курсы, ушедший ученик — оценки.
Правило: участников организации не удаляют, а блокируют (`disabled_at`). Курсы
передаются другому учителю из `/org`. Удаление симуляции, вставленной в курс,
спрашивает «используется в N курсах»; блок после удаления показывает «симуляция удалена».

**Доступ к симуляции.** В `storage.ts` рядом с `owned()` появляется `canView(userId, simId)`:
владелец, **или** симуляция в каталоге, **или** она вставлена в опубликованный курс,
открытый группе пользователя. Правка и удаление — только владельцу.

## 5. Циклы

Общие правила: `npm test` зелен без базы; наборы с Postgres читают
`SHOWMEHOW_TEST_DATABASE_URL`; чистая логика (генерация логинов, разбор CSV, сравнение
состояния с целью, лимиты) живёт в модулях без базы и покрыта юнитами.

### Цикл 0 — Модель доступа

**Даёт** фундамент для всего остального; экранов почти нет.

- Миграция: таблицы цикла 0 из раздела 4.
- Вход по одному полю «почта или логин». `findUserByEmail` становится
  `findUserByIdentifier`.
- **Лимит входа переделан.** Неудачи считаются по идентификатору (10 за 15 минут,
  одинаково для существующего и несуществующего аккаунта) и отдельно по IP с высоким
  порогом (300), чтобы школьный NAT не блокировал класс. Отдельный, более низкий
  порог по IP для несуществующих аккаунтов рассматривался, но отклонён на ревью: его
  исчерпание само выдавало клиенту, какие из перебираемых логинов существуют.
- Короткие сессии для учеников: 12 часов без продления. На общем компьютере утренний
  ученик не оставит аккаунт дневному. Настройка организации может сделать их длинными.
- Охранники в `src/lib/org/access.ts`: `membershipsOf`, `requireOrgRole`,
  `requirePlatformAdmin`, `canViewCourse`. Вызываются в роутах, middleware не меняется.
- Навигация получает список разделов от сервера.
- Принудительная смена пароля: при `must_change_password` все страницы, кроме смены
  пароля, уводят на неё.

**Приёмка:** пользователь без членств не видит изменений; учитель организации А
получает 404 на всё из Б; 30 входов подряд с одного IP с опечатками не блокируют
31-го ученика.

### Цикл 1 — Эксплуатация под нагрузку

**Даёт** платформу, которая переживает рестарт, второй экземпляр и утро понедельника.
Идёт параллельно с циклом 0 и **обязан закончиться до пилота в школе**.

- **Воркер отдельно от веба.** `scripts/worker.ts` — отдельная служба systemd. Берёт
  задания из таблицы `jobs` через `SELECT ... FOR UPDATE SKIP LOCKED`, держит аренду
  `locked_until` и продлевает её. Упавший воркер — аренда истекла, задачу подхватил
  следующий. Новой зависимости не нужно: Redis и BullMQ здесь дороже пользы.
- **Прогресс через базу.** Воркер пишет события в `jobs.events`, веб отдаёт их по SSE,
  читая базу с `LISTEN/NOTIFY`. Карты в памяти уходят — и вместе с ними болезнь
  `next dev`.
- **Параллелизм настраивается** числом воркеров и `WORKER_CONCURRENCY`. Лимит «одна
  активная генерация на человека» становится запросом к `tasks`.
- **Приоритет**: у учителя организации генерация идёт раньше B2C-пробника. Поле
  `priority` в `jobs`.
- **Доработка тоже через очередь.** Сейчас она идёт прямо в HTTP-запросе и поднимает
  Chromium в обход ограничителя.
- **Лимиты входа и чата в базе**, а не в памяти процесса.
- **HTTPS** через уже стоящий Caddy, домен от владельца. Без него пароли учеников идут
  открытым текстом, а VR не работает.
- **Бэкапы**: ежесуточный `pg_dump` и копия `data/` с ротацией; проверенное
  восстановление на чистой машине.
- **Наблюдаемость**: `/api/health`, журнал ошибок провайдера, длина очереди и среднее
  ожидание — в админку (цикл 6).
- **Нагрузочная проверка**: 300 одновременных учеников читают курс и сдают задания;
  20 учителей одновременно запускают генерацию. Цель: страница курса быстрее 500 мс,
  генерации стоят в очереди с честной позицией, веб не тормозит.

**Приёмка:** рестарт приложения посреди генерации не теряет задание; два экземпляра
веба работают с одной базой; нагрузочный сценарий проходит.

### Цикл 2 — Кабинет организации

**Даёт** админу организации учителей, группы и учеников.

- **Учителя**: приглашение ссылкой на 7 дней. Ссылку копируют и отправляют сами —
  почтового сервиса нет.
- **Группы**: «7А», «ИС-21»; назначение учителей; архив в конце года с переводом
  учеников в новую группу одной операцией.
- **Ученики, три способа:**
  1. **Массово.** Вставить список «Фамилия Имя» или загрузить CSV. Предпросмотр с
     подсветкой дублей и опечаток, затем создание. Логины вида `ivanov.i.<slug>`,
     при коллизии — цифра. Символа `@` в логине нет: по нему вход отличает логин от почты. Пароли — три коротких слова без похожих букв
     («лиса-дом-семь»): их диктуют вслух и печатают. Печатная страница с карточками
     под разрезание.
  2. **По коду группы.** Студент с собственным аккаунтом вводит код в профиле.
  3. **Поштучно.**
- **Сброс пароля ученику** — учителем его группы, не только админом. Иначе на каждом
  уроке очередь к админу.
- **Повторная печать** листа — только для паролей, которые ещё не сменены. Сменённый
  пароль не восстанавливается, только сбрасывается.
- **Настройки**: доступ учеников к генерации (по умолчанию выкл.), доступ к
  Прометею (по умолчанию вкл.), длина сессий.

**Приёмка:** 30 учеников из CSV заводятся за минуту; лист печатается; ученик входит,
меняет пароль и видит «Курсы»; учитель сбрасывает пароль ученику своей группы.

### Цикл 3 — Курсы

**Даёт** учителю конструктор, ученику — чтение.

**Учитель:**
- Курс: название, предмет, описание, группы; черновик, опубликован, архив.
- Редактор: темы слева, блоки темы справа, перетаскивание, дублирование блока.
  Автосохранение. Предпросмотр «глазами ученика».
- Блок `text`: markdown с превью; формулы — решить в спеке (KaTeX, если нужны).
- Блок `simulation`: один диалог «личная библиотека + каталог», поиск и превью.
- Кнопка «Сгенерировать для этого блока»: уводит в мастерскую, результат сам встаёт
  в блок. Квота — учителя.
- Блок `lab`: сцена и станция, открывается встроенной рамкой и кнопкой «в очках» с QR.
- Открытие темы по дате (`opens_at`) — учитель готовит курс заранее.
- Копирование курса на следующий год; соавторы-учителя.

**Ученик:**
- `/learn`: мои курсы с прогрессом.
- Тема: блоки подряд, симуляция во встроенной рамке с кнопкой «на весь экран».
- Отметка «просмотрено» по темам — учитель видит, кто дошёл.
- Экран рассчитан на телефон: у многих учеников другого устройства нет.

**Приёмка:** учитель собирает курс из трёх тем с текстом и двумя тренажёрами за десять
минут и публикует группе; ученик группы видит курс, ученик другой группы — 404;
удаление симуляции не роняет курс; курс читается на телефоне.

### Цикл 4 — Задания и учительская

**Типы заданий:**

| Тип | Что делает ученик | Проверка |
|---|---|---|
| `choice` | выбирает один или несколько вариантов | автоматически |
| `number` | вводит число, можно с единицами | автоматически, с допуском |
| `text` | пишет ответ, может приложить снимок симуляции | учитель (в цикле 8 — с подсказкой ИИ) |
| `sim_state` | добивается в симуляции целевого состояния и сдаёт | автоматически по состоянию кита |

К любому типу можно привязать **стенд** — симуляцию или лабораторию, открытую рядом
с вопросом. Так «изучи на тренажёре и ответь» — это `choice` или `text` со стендом.

**Как учитель задаёт `sim_state` без программирования.** Открывает симуляцию в режиме
«задать цель», выставляет контролы, нажимает «Зафиксировать». Страница спрашивает
состояние у рамки (`sim-state-request` → `sim-state`, новый ответ харнесса), и сервер
сохраняет цель как список `{ name, value, tolerance }` по контролам плюс выбранные ключи
`getState()`. Учитель правит допуски и убирает лишнее. При сдаче страница тем же мостом
берёт состояние ученика, сервер сравнивает и пишет `auto_score`. Ученик видит, что
сошлось, если учитель не выбрал «не подсказывать».

Честные ограничения:
- работает только для симуляций на ките с `SimUI.expose`; редактор скажет, если
  симуляция не поддерживает проверку, и предложит `text`;
- состояние присылает браузер ученика, его можно подделать через инструменты
  разработчика. Для текущего контроля этого достаточно; для оценки «в журнал» учитель
  видит снимок и может перепроверить. Писать это в интерфейсе прямо не нужно, но в
  документации для школ — нужно.

**Ученик:** статус «не начато / черновик / сдано / возвращено / проверено», оценка и
комментарий, повторная попытка — если задание разрешает. Черновик сохраняется сам.

**Учитель:**
- «Ответы» по заданию: ученик × статус × автооценка × оценка; переход к следующему
  непроверенному одной клавишей;
- «Вернуть на доработку» с комментарием;
- «Журнал» по курсу: ученики × задания, фильтр «непроверенные», выгрузка CSV;
- срок сдачи, поздняя сдача помечается.

**Приёмка:** все четыре типа проходят путь «создал → сдал → проверил → ученик увидел»;
`sim_state` считает совпадение с допуском; учитель ничего не программирует; журнал
выгружается и открывается в Excel.

Если нужен ранний показ школе, `text` и `choice` выделяются в **цикл 4a** и идут сразу
за циклом 3; `sim_state` и журнал — в 4b.

### Цикл 5 — Задания в VR-лабораториях

**Даёт** то, чем Tesseract отличается от любой LMS: «смешай реагенты и получи осадок
гидроксида меди».

- **Мост событий.** Сцена лаборатории, открытая во встроенной рамке, шлёт родителю
  `lab-event`: `{ lab, station, event, data }`. Для химии это одна строка в месте, где
  вызывается `react()`: реакция, продукт, эффект, список добавленных реагентов.
  Для информатики — «массив отсортирован», алгоритм, число шагов. Для физики — угол
  падения, наблюдённый спектр, выбранная планета.
- **Реакции получают стабильные идентификаторы** в таблице `PAIRS`, чтобы цель задания
  не зависела от текста подписи.
- **Тип задания `lab_goal`**: учитель выбирает сцену и цель из списка, который сцена
  сама объявляет (`LAB_GOALS` рядом с чистой логикой): «получить осадок Cu(OH)₂»,
  «вызвать выделение газа», «отсортировать быстрой за ≤ N шагов», «окрасить пламя в
  зелёный». Список — подсказка: к нему всегда можно добавить вопрос `text` «опиши, что
  увидел».
- **Журнал попытки**: последовательность событий сохраняется в `evidence`. Учитель видит
  не только «получил», но и «сначала перепутал реагенты».
- **В очках** задание работает только при входе с аккаунтом: страница задания в очках
  открывается по QR с одноразовым кодом, который привязывает сцену к попытке ученика.
  Страницы сцен без задания по-прежнему открыты без входа.

**Приёмка:** в химии три цели, в информатике две, в физике одна; сдача засчитывается
автоматически; журнал событий виден учителю.

### Цикл 6 — Админка платформы

**Даёт** владельцу экран вместо `psql` и ssh. До этого цикла роль админки играют
скрипты `scripts/*.ts` по образцу `migrate-to-db.ts`.

- **Организации**: список, создание с первым админом (одноразовый пароль на экране),
  архив, переход «глазами админа организации» (только чтение).
- **Пользователи**: поиск, карточка с членствами, сброс пароля, блокировка, смена
  платформенной роли, завершение всех сессий.
- **Использование**: генерации и сообщения Прометея по дням, организациям и людям;
  расход токенов; очередь сейчас и среднее ожидание; ошибки провайдера.
- **Каталог**: отметить симуляцию общей, проверить перед публикацией, снять.
- **Настройки платформы**: открыта ли регистрация, квоты B2C, лимит Прометея.
- **Журнал действий** админа.

**Приёмка:** владелец создаёт организацию, сбрасывает пароль и закрывает регистрацию
без доступа к серверу; `user` получает 404 на `/admin/*`.

### Цикл 7 — Персонализация и Прометей

Не зависит от циклов 2–6. Можно вести вторым потоком сразу после цикла 0.

**Профиль.** Блок «Обо мне»: интересы чипами-подсказками («например: футбол, игры,
музыка, кулинария, космос, авто, медицина, рисование, танцы, программирование») и
**равноправное поле «своё»** — подсказка не должна становиться рамкой. Уровень (уже
есть), несколько слов о себе. Интересы не видят ни учитель, ни организация, ни админ.
При первом входе в Прометей — короткий вопрос «чем увлекаешься?», если интересов нет.

**Чат `/prometheus`.**
- Беседы слева, беседа справа, ответ стримится.
- Роль `tutor` в провайдере; своя модель задаётся в `roles.tutor`.
- `streamChat` поверх `chat.completions.create({ stream: true })`, клиенту — SSE.
  Состояния в памяти процесса нет: поток читается напрямую, сообщение пишется в базу
  по завершении.
- **Как объясняет:** метафора из интересов → честная формулировка без метафоры →
  один вопрос на проверку понимания. Не выдумывает факты; если не знает — говорит.
- **Что показывает:** если в каталоге или в библиотеке человека есть подходящая
  симуляция или лаборатория — карточка «Открыть». Если нет — кнопка «Сгенерировать»
  с готовым запросом в мастерскую. Сам генерацию не запускает: это квота и минуты.
  Ссылки только на существующее — список кандидатов подаётся модели, а не
  придумывается ею.
- **Вход из урока:** «Спросить Прометея» в теме передаёт контекст темы и блока.
- **Режим для задания.** Если ученик пришёл из задания, Прометей наводит, но не
  решает: не называет ответ `choice` и `number`, не пишет текст за ученика.
  Учитель может выключить Прометея для конкретного задания (контрольная).
- **Безопасность для детей.** Системные правила: возрастная уместность, отказ от
  тем вне учёбы с мягким возвратом, без сбора личных данных. Текст урока подаётся как
  данные, а не инструкции — защита от подсказок, вставленных в блок.
- **Лимит**: сообщений в сутки на человека (порядок 50 для B2C, настройка организации
  для B2B), считается по `messages`. Без лимита открытая регистрация плюс бесплатный
  чат — расходы владельца без потолка.
- Удаление беседы пользователем.

**Примеры** (интерес × тема → объяснение → что показать). Это не правила промпта, а
проверочные сценарии для `evals/`:

| Интерес | Тема | Через интерес | Показать |
|---|---|---|---|
| Футбол | Пузырьковая сортировка | тренер выстраивает шеренгу по росту: идёт вдоль, меняет соседей, если левый выше; за проход самый высокий «всплывает» в конец | «Зал алгоритмов», сортировки |
| Футбол | Эффект Магнуса | почему закрученный мяч огибает стенку: разное давление по сторонам вращающегося мяча | сгенерировать: траектория с ползунком закрутки |
| Футбол | Вероятность | почему серия пенальти — почти лотерея: 75 % на удар и распределение исходов пяти ударов | сгенерировать: Монте-Карло серий |
| Minecraft | Рекурсия, деревья | крафт кирки: палки и слитки, для слитков — руда и печь; дерево рецептов раскрывается вглубь | «Зал алгоритмов», дерево поиска |
| Игры | Клеточный автомат | редстоун: клетка смотрит на соседей и решает, гореть ли в следующем такте | сгенерировать: «Жизнь» с кистью |
| Игры | Векторы | прыжок персонажа: скорость — стрелка, гравитация каждый кадр укорачивает её вертикальную часть | «Оптический стол», гравитационная комната; или сгенерировать бросок с векторами |
| Музыка | Интерференция, Фурье | аккорд — сумма синусоид; биения при настройке гитары — две близкие частоты | демо «Интерференция» |
| Кулинария | Скорость реакции | тесто в тепле и в холодильнике: чаще столкновения — быстрее реакция | сгенерировать: реакция с ползунком температуры |
| Кулинария | Осмос | огурец в рассоле сжимается, изюм в воде набухает | демо «Осмос» |
| Кулинария | Кислоты и индикаторы | краснокочанная капуста меняет цвет от уксуса и соды — природный индикатор | «Стол реакций»: лакмус |
| Авто | КПД, термодинамика | четыре такта своего мотора; куда уходит бо́льшая часть энергии бензина | демо «ДВС» |
| Космос | Законы Кеплера | почему низкий спутник летит быстрее геостационара | демо «Орбиты Кеплера» |
| Соцсети | Обход в ширину | видео расходится волной: друзья, потом друзья друзей | «Зал алгоритмов», обход графа |
| Бег | Кинематика | 100 метров: где ускорение, где плато скорости | сгенерировать: v(t) по отрезкам |
| Деньги | Экспонента | «по 100 в месяц» против «+5 % к тому, что есть» | сгенерировать: два графика роста |
| Медицина | Нейрон | нерв как провод с порогом: почему обезболивающее «выключает» сигнал | сгенерировать: потенциал действия |
| Рисование | Преломление | ложка в стакане «ломается»; как честно рисовать блик | «Оптический стол», демо «Преломление» |
| Танцы | Колебания, резонанс | качели и такт: толчок в такт раскачивает, не в такт — гасит | демо «Маятник» |
| Без интересов | любая | нейтральное объяснение из быта | по каталогу |

Эвал по каждой строке проверяет: (а) интерес использован, (б) есть формулировка без
метафоры, (в) нет выдуманных фактов, (г) ссылка ведёт на существующее, (д) в режиме
задания ответ не выдан.

**Приёмка:** «футбол» получает сортировку на футболистах; без интересов — нейтрально;
лимит срабатывает; «Открыть» ведёт на реальную симуляцию; из задания ответ не выдаётся.

### Цикл 8 — ИИ для учителя

Использует пайплайн и роль `tutor`; всё, что генерирует ИИ, учитель видит и правит
до публикации.

- **Черновик курса.** «Физика, 8 класс, тепловые явления, 6 уроков» → темы, текстовые
  блоки, подбор тренажёров из каталога, пометки «сгенерировать тренажёр» там, где
  подходящего нет.
- **Вопросы по симуляции.** Модель получает план симуляции и список её контролов и
  предлагает `choice`, `number` и `sim_state` с целями по реальным контролам. Сейчас
  полный план (`PlanSpec`: параметры, законы, цели) после генерации теряется — в журнале
  задания остаётся только краткая сводка. Цикл 8 начинается с того, что план
  сохраняется рядом с артефактом; для старых симуляций контролы снимаются мостом кита.
- **Подсказка оценки** для `text`: балл и комментарий по критериям учителя. Учитель
  подтверждает или правит; в журнал идёт только его оценка.
- **Сводка по заданию**: «12 из 25 перепутали массу и вес» — по ответам группы.

**Приёмка:** черновик курса собирается за минуту и открывается в редакторе;
вопросы ссылаются только на существующие контролы; подсказка оценки не попадает в
журнал без подтверждения.

## 6. Порядок

```
цикл 0 ──┬── цикл 2 ── цикл 3 ── цикл 4a ── цикл 4b ── цикл 5
         ├── цикл 7 ──────────────────────────────── цикл 8
         └── цикл 6
цикл 1 (параллельно с 0, закончить до пилота)
```

**Один поток:** 0 → 1 → 2 → 3 → 4a → **пилот** → 4b → 7 → 5 → 6 → 8.

**Два потока:** первый ведёт 0 → 2 → 3 → 4, второй — 1 → 7 → 6. Цикл 5 и 8 — после.

Админка идёт поздно намеренно: первые месяцы её заменяют скрипты, а владелец платформы
один. Прометей — раньше админки, потому что он виден каждому пользователю.

## 7. Пилот в одной школе

Цель — проверить продукт на живом классе до масштабирования.

**Состав:** одна организация, 2–3 учителя, 3–4 группы, 60–100 учеников, 4 недели.
**Готово к пилоту:** циклы 0, 1, 2, 3, 4a.
**Что меряем:**

| Метрика | Порог успеха |
|---|---|
| Ученики, вошедшие в первую неделю | 80 % |
| Время учителя на урок из трёх блоков | до 15 минут |
| Сданные задания от выданных | 60 % |
| Обращения «не могу войти» | меньше одного на урок |
| Ожидание генерации учителем в 8:00 понедельника | до 5 минут до старта |

**Что собираем:** короткое интервью с учителями в конце каждой недели; список
«хотел сделать, но не смог». Этот список определяет порядок циклов после пилота.

## 8. Сквозные решения

- **Платформенных ролей две.** Учитель и ученик — членства, не `users.role`.
- **404 вместо 403** для всего чужого: организации, курса, ответа, беседы.
- **Проверка доступа в роуте**, как сейчас. Охранники — функции в `src/lib/org/`.
- **Новые таблицы — только Postgres**, по образцу `auth/users.ts`. `MetaRepo` с двумя
  драйверами остаётся только для симуляций.
- **Новые зависимости — только с причиной в спеке цикла.** Очередь — на Postgres,
  без Redis. Markdown — решается в цикле 3.
- **Генерация в LMS — учительская.** Ученикам — по настройке организации.
- **Приватность:** беседы и интересы не видит никто, кроме владельца; админ видит
  только счётчики.
- **Интерфейс** — в существующей системе: `globals.css`, панели, сегменты, чипы.
  Второго стиля для админки не будет.
- **Язык интерфейса** — пока русский, но строки новых экранов собираются в один модуль
  на раздел, чтобы казахский не превратился в поиск по всему коду (см. вопросы).

## 9. Риски

| Риск | Что делаем |
|---|---|
| `email NOT NULL` расползается по коду | одна правка в цикле 0 с тестами; логин — новый ключ |
| Класс блокирует себе вход лимитом по IP | лимит по аккаунту, высокий порог по IP (цикл 0) |
| Очередь генераций в памяти не выдерживает утро понедельника | воркер и очередь в базе (цикл 1) до пилота |
| Общий школьный компьютер оставляет чужой аккаунт открытым | короткие сессии учеников (цикл 0) |
| `sim_state` работает не для всех симуляций | редактор честно говорит и предлагает `text` |
| Состояние симуляции подделывается в браузере | для текущего контроля достаточно; снимок виден учителю |
| Учитель удаляет симуляцию из курса | блок «удалена»; предупреждение при удалении |
| Ушедший учитель уносит курсы | блокировка вместо удаления; передача курсов |
| Правка задания после сдачи | ревизии блоков; пересчёт по запросу |
| Прометей жжёт ключ | суточный лимит (цикл 7), закрытие регистрации из админки (цикл 6) |
| Прометей решает контрольную | режим задания; выключение на задании |
| Подсказка, вставленная в текст урока, ломает Прометея | контекст урока подаётся как данные |
| Печатный лист паролей — единственная копия | повторная печать для несменённых; сброс учителем |

- Интеграции: LTI, Google Classroom, электронные дневники.
- Родительский доступ.
- Прометей внутри симуляции («объясни, что я сейчас вижу») — после цикла 5, когда мост
  состояния уже есть.
- Генерация новых VR-лабораторий.
- Мультиплеер в лабораториях.

## 11. Открытые вопросы

Ответы меняют спеки циклов, не эту карту. Пока принято так:

1. **Ученикам нужна генерация?** Принято: нет, по умолчанию выключена.
2. **Регистрация остаётся открытой?** Принято: да, с квотой и лимитом чата; закрывается
   переключателем в админке. Решение за владельцем.
3. **Кто заводит группы?** Принято: админ организации и учитель; админ видит все.
4. **Каталог пополняет только админ платформы?** Принято: да; «предложить в каталог» —
   позже.
5. **Нужны ли формулы в тексте урока?** Решить в спеке цикла 3.
6. **Казахский язык интерфейса и Прометея.** Для школ Казахстана, скорее всего, нужен.
   Принято: не в этих циклах, но строки собираются так, чтобы перевод был дешёвым.
   Прометей по-казахски — вопрос качества модели, проверяется эвалом.
7. **Персональные данные несовершеннолетних.** Сервер уже в Казахстане. Перед пилотом
   нужно проверить с юристом требования закона РК о персональных данных: согласие
   родителей, состав хранимых данных, срок хранения. Принято: храним минимум — логин,
   имя, группа; почта ученика необязательна.
8. **Название раздела ученика:** «Курсы».
