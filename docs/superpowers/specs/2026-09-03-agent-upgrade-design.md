# ShowMeHow — ревизия и спецификация «Агент 2.0»

**Дата:** 2026-09-03
**Статус:** черновик на утверждение
**Ветка-основание:** `jobs-and-progress` @ 2aa1900

## 0. Кратко

Пайплайн работает и хорошо обвязан (jobs, SSE, тесты, демо-гейт), но его потолок качества
задан тремя вещами: **одноразовая генерация всего HTML по тонкой спецификации**,
**слабая проверка** (только «нет ошибок в консоли + картинка меняется») и **бедный UI-kit**,
из-за которого модель либо рисует всё руками, либо получает голую панель со слайдерами.
Ручной эталон `demos/engine` лучше любой генерации именно потому, что в нём есть то, чего
нет в ките и в промпте: баннер такта, формула с живыми числами, частицы, вспышка, камера.

Спека предлагает довести систему до уровня, где **«ДВС, но лучше»** — это штатный
результат, а не ручная работа. Ключевые ставки (по убыванию эффекта на результат):

1. **SimUI 2.0** — графики, показания, формулы, баннер фазы, легенда, пресеты, сценарий
   («история»), 3D-хелперы (орбита камеры, подписи). Модель собирает из блоков, а не
   рисует руками.
2. **Планировщик 2.0** — спецификация с раскадровкой, инвариантами физики и лейаутом
   экрана; спецификация сохраняется вместе с симуляцией.
3. **Проверка 2.0** — поведенческие пробы (слайдеры/пауза/сброс реально работают),
   физические ассерты (планировщик задаёт инварианты, скрипт их проверяет в странице),
   критик видит больше кадров и получает структурированный отчёт. Замечания критика
   чинятся, а не только доносятся судье.
4. **Эталоны как few-shot** — ближайшая демка подаётся генератору целиком.
5. **Надёжность вывода** — `max_tokens`, продолжение при обрыве, модели по ролям,
   телеметрия токенов/времени.
6. **UI** — галерея кандидатов с ручным выбором, доводка как job, режим «сначала план».

## 1. Ревизия кода

### 1.1 Что хорошо (не трогаем)

- Чистое разделение: `provider` → `stages` → `run` → `jobs` → SSE → `deriveProgress`
  (чистая функция от журнала событий). Реплей после перезагрузки работает.
- `verifyCandidate` с best-so-far и рангом «заражён CDN < статика < анимация»
  (`src/lib/pipeline/stages.ts:56-90`).
- Reinstrument-on-read: правки рантайма ретроактивны для старых симуляций
  (`src/lib/artifact.ts:110-126`, `src/lib/storage.ts:50`).
- Демо-гейт: каждая демка обязана рендериться без ошибок и анимироваться.
- 183 юнит-теста зелёные; 14 падений в этой среде — только из-за отсутствия Chromium
  Playwright (`renderer.test`, `integration/demos.test`), не дефект кода.

## 2. Целевой уровень: «ДВС, но лучше»

Референс — то, что пайплайн обязан выдавать штатно на промпт про двигатель (и аналогично
на любую тему). Это чек-лист для планировщика, судьи и evals.

**Сцена.** 3D в разрезе (гильза полупрозрачная, поршень, шатун, коленвал, два клапана,
свеча), орбита камеры мышью + пресеты ракурсов («сбоку», «сверху», «в разрезе»),
переключатель «разрез/цельный», вспышка и частицы впуска/выпуска.

**Приборы.** Баннер текущего такта (1/4, цвет, подпись клапанов); показания: обороты,
угол коленвала, положение поршня, давление, температура; **индикаторная p-V диаграмма**,
в реальном времени рисующая цикл Отто по тактам; график положения поршня и подъёма
клапанов от угла (диаграмма фаз газораспределения).

**Формулы.** Панель с KaTeX: кинематика КШМ `x(θ)`, адиабата `pV^γ = const`, КПД цикла
Отто `η = 1 − ε^{1−γ}` — с **подстановкой живых значений**.

**Управление.** Слайдеры: обороты, степень сжатия, длина шатуна/радиус кривошипа;
пресеты «холостой ход / город / трасса»; замедление 0.1×; шаг по 10° коленвала;
скраббер по циклу 0-720°.

**Сценарий.** Кнопка «Рассказать»: 5-7 шагов с подсветкой детали, текстом и нужным
ракурсом камеры (впуск → сжатие → искра → рабочий ход → выпуск → «что даёт степень
сжатия»). Шаги проходятся кликом, симуляция ставится на паузу/замедляется в нужный момент.

**Педагогика.** Цели обучения в панели; «предскажи → проверь»: вопрос («что будет с КПД
при росте ε?») с кнопкой-ответом; понятные единицы, русские подписи.

**Надёжность.** Пауза замораживает всё; сброс возвращает θ=0 и очищает частицы;
слайдеры меняют картину немедленно; на 390×844 панели свёрнуты, сцена не перекрыта;
без ошибок в консоли 10 с; 60 fps на ноутбуке.

Обобщение на другие темы: у каждой симуляции есть **сцена + приборы + формулы с живыми
числами + пресеты + сценарий из шагов + один «вау-момент»** (искра, резонанс, полное
внутреннее отражение, коллапс орбиты).

## 3. Архитектура «Агент 2.0»

```
Промпт (+картинка)
   ▼
① ПЛАНИРОВЩИК 2.0 ─── Spec v2: физика + величины + инварианты + лейаут +
   │                   графики + пресеты + раскадровка + вау-момент + библиотеки
   │   (опц.) ⏸ «Сначала план»: преподаватель правит spec в UI и подтверждает
   ▼
② ГЕНЕРАЦИЯ N кандидатов  ← правила + SimUI 2.0 doc + ближайший ЭТАЛОН целиком
   │                          (max_tokens, продолжение при обрыве)
   ▼
③ ПРОВЕРКА 2.0 (каждый):
   рендер → ошибки/CDN → ПРОБЫ (слайдеры, пауза, сброс, 8 с, мобайл, NaN, fps)
   → АССЕРТЫ физики (скрипт по инвариантам из spec, через SimUI.expose)
   → автопочинка по структурированному отчёту (до 2)
   → КРИТИК (vision): кадры t=0/1/3/8 + после проб + мобайл, отчёт проб
   → если критик нашёл физ.ошибки → целевая починка (1 раз) → повторные пробы
   ▼
④ СУДЬЯ 2.0 — рубрика ×6 + детерминированные сигналы (пробы, ассерты);
   оценки видны в UI; ГАЛЕРЕЯ: все живые кандидаты в iframe, ручной выбор
   ▼
⑤ ДОВОДКА — рефайнер видит spec + скриншоты + замечания + полные правила;
   стоп по «улучшение < δ» или порогу; каждая итерация проходит ③
   ▼
Артефакт + spec.json + quality.json → библиотека
```

Ниже — компоненты. Каждый описан как отдельная единица с интерфейсом, зависимостями и
тестами; фазы поставки — в §5.

### 3.1 SimUI 2.0 (`src/lib/runtime.ts` → разбить на `runtime/{harness,kit-css,kit-js,doc}.ts`)

Принцип: всё, что в хороших демках рисуется руками через `position:fixed`, становится
примитивом кита. Промпт запрещает рукописные панели, и теперь это не мешает «крутизне».
ES5, без зависимостей, идемпотентно, работает в ретроактивном reinstrument.

Новые примитивы (все возвращают DOM-элемент или контроллер):

| Примитив | Сигнатура | Назначение |
|---|---|---|
| `SimUI.readout` | `({label, unit, digits, corner}) → {set(v)}` | Показание величины в панели «Величины»; несколько readout стекуются. |
| `SimUI.chart` | `({title, xLabel, yLabel, series:[{name,color}], maxPoints, xRange?, yRange?, mode:'time'\|'xy', corner}) → {push(x, ys[]), clear()}` | Живой график на собственном canvas с осями, сеткой, легендой, автомасштабом. Режим `xy` — для p-V, фазовых портретов. Заменяет chart.js. |
| `SimUI.formula` | `({title, tex, vars:{name:{label,unit}}, corner}) → {set(values)}` | KaTeX-формула + строка подстановки живых значений. KaTeX грузится китом лениво из whitelist; при недоступности — текст. |
| `SimUI.banner` | `({items:[{name,sub,color}]}) → {set(index)}` | Крупный баннер фазы/такта/режима сверху по центру (как в ДВС). |
| `SimUI.legend` | `({items:[{color,label}], corner})` | Легенда цветов. |
| `SimUI.select` / `toggle` / `button` | как slider, в панели управления | Дискретные параметры, переключатели («разрез»), действия («добавить частицу»). |
| `SimUI.presets` | `({items:[{label, values:{param:v}}]})` | Кнопки-пресеты; кит сам двигает слайдеры и вызывает их onChange. |
| `SimUI.speed` | `({values:[0.1,0.5,1,2]}) → {get()}` | Множитель времени; интегрирован в playPause. |
| `SimUI.scrubber` | `({min,max,unit,onSeek}) → {set(v)}` | Полоса времени/фазы с перетаскиванием (0-720° для ДВС). |
| `SimUI.story` | `({steps:[{title, text, onEnter, onLeave}]})` | Сценарий: панель шага с «Далее/Назад», шаги вызывают колбэки (подсветить, повернуть камеру, замедлить). Кнопка «Рассказать» в панели управления. |
| `SimUI.quiz` | `({question, options, answer, explain})` | «Предскажи → проверь». |
| `SimUI.goals` | `(['...'])` | Панель целей обучения (свёрнута по умолчанию). |
| `SimUI.expose` | `({getState, setParam, step, reset})` | Контракт интроспекции для проверки (§3.4). Обязателен. |

3D-хелперы (`SimUI.three`, загружаются только если артефакт импортирует three):
кит инжектит `<script type="importmap">` с `three` и `three/addons/` на whitelist-URL;
whitelist расширяется на `three@0.164.0/examples/jsm/`. Промпт даёт рецепт:
`OrbitControls`, `CSS2DRenderer` для подписей, пресеты камеры через
`SimUI.select`, `renderer.setPixelRatio(min(dpr,2))`, `preserveDrawingBuffer` для
скриншотов.

Слои и лейаут: панель управления `tr`, баннер сверху по центру, `story` снизу по центру,
readout/chart/formula/legend — по углам через существующий механизм стекирования;
на мобиле всё, кроме баннера и story, свёрнуто. Единая типографика/контраст — уже в CSS.

Документация кита (`UIKIT_DOC`) переписывается как компактный API-справочник с одним
мини-примером на примитив. Демо `demos/engine` переписывается на SimUI 2.0 и становится
«ДВС v2» из §2 — одновременно эталон и приёмочный тест кита.

Тесты: юнит на `instrument/reinstrument` (без изменений контракта), интеграционный
«kit smoke»: фикстура использует каждый примитив, рендерится без ошибок, пробы проходят.

### 3.2 Планировщик 2.0 (`PlanSpec` v2, `prompts.ts`, `types.ts`)

```ts
interface PlanSpecV2 {
  version: 2;
  title; subject; mode: '2d'|'3d'; libs: ('three'|'p5'|'matter'|'katex')[];
  learningGoals: string[];
  physics: { summary: string; equations: {tex: string; meaning: string}[];
             assumptions: string[]; };
  quantities: { name: string; label: string; unit: string; formula?: string }[]; // что показывать/строить
  parameters: SimParameter[];                     // слайдеры (2-5)
  controls: { type:'select'|'toggle'|'button'; name; label; options?: string[] }[];
  presets: { label: string; values: Record<string, number> }[];
  charts: { title; x: string; y: string[]; mode: 'time'|'xy' }[];
  invariants: { id: string; description: string; check: string }[];  // см. §3.4
  layout: { scene: string; banner?: {items: string[]}; panels: {corner; content}[] };
  story: { title: string; text: string; action: string }[];           // 4-7 шагов
  wowMoment: string;
  visualPlan: string;
}
```

Планировщик получает чек-лист §2 как критерий «полноты» и обязан заполнить все поля.
`invariants[].check` — псевдокод/JS-выражение над `getState()` (пример:
`abs(s.energy - s.energy0) / s.energy0 < 0.02` или `period ≈ 2π√(L/g) ± 5%`).
Спецификация сохраняется в `data/simulations/<id>/spec.json`, показывается в PlanCard
(раскадровка и инварианты — сворачиваемые секции) и используется доводкой и судьёй.

Режим «Сначала план» (переключатель в композере): после `plan-ready` job ждёт события
`plan-approved` с (возможно отредактированным) spec: UI даёт править параметры,
пресеты, шаги сценария и вау-момент. Таймаут ожидания — 30 мин, затем job отменяется.

### 3.3 Эталоны как few-shot (`src/lib/exemplars.ts`)

- Каждая демка получает в `meta.json`: `mode`, `libs`, `keywords`, `techniques`
  (например `particles`, `kinematic-chain`, `vector-field`, `wave-grid`).
- Подбор: скоринг по совпадению `subject`, `mode`, ключевых слов промпта/spec и техник
  (без эмбеддингов; детерминированно, покрыто юнит-тестом). Один лучший эталон (не более
  ~25 КБ) вставляется в промпт генератора целиком с пометкой «эталон качества; тема другая,
  копируй структуру и приёмы, не тему».
- Если эталон 3D, а spec 2D (или наоборот) — берётся лучший по режиму.
- «Сделать эталоном»: кнопка в библиотеке копирует симуляцию в `demos/<slug>/` с
  метаданными (только для локального инструмента — фича разработчика/преподавателя).
- Каждый эталон обязан использовать только SimUI 2.0 (демо-гейт проверяет отсутствие
  рукописных `position:fixed`).

### 3.4 Проверка 2.0 (`renderer.ts`, новый `src/lib/pipeline/probes.ts`, `assertions.ts`)

**Интроспекция.** Рантайм (harness) предоставляет RPC: страница отвечает на
`page.evaluate(() => window.__smh.probe(...))`. `SimUI.expose` регистрирует
`getState/setParam/step/reset`; кит сам знает свои слайдеры/кнопки (`__smh.controls()`).

**Пробы** (детерминированные, без LLM), результат — `ProbeReport`:

| Проба | Как | Провал |
|---|---|---|
| `animates` | кадры t=0.3/1.2/3/8 с; попарные различия | нет изменений после 3 с (кроме явно статичных режимов из spec) |
| `pause` | клик Пауза → 2 кадра с интервалом 700 мс | кадры отличаются |
| `reset` | сдвинуть время, Сброс → `getState()` ≈ начальному | state не вернулся |
| `sliders` | для каждого слайдера: min, max → кадр и `getState()` | кадр/состояние не изменились; ошибка в консоли |
| `controls` | каждая кнопка/toggle/select/пресет — клик | ошибка; пресет не переставил слайдеры |
| `nan` | `getState()` и текст readout'ов | `NaN`/`Infinity`/`undefined` |
| `mobile` | вьюпорт 390×844, кадр | ошибка; панели не свёрнуты; сцена < 50 % площади |
| `perf` | fps за 2 с | < 25 fps (предупреждение, не провал) |
| `cdn` | сетевые запросы страницы | URL вне whitelist (блокируется `page.route`, фиксируется) |
| `story` | если есть story: пройти все шаги | ошибка на шаге |

Все пробы дают текстовое описание провала для фиксера («слайдер "Обороты" на максимуме не
меняет картину и `getState().rpm` остался 600»). Скриншоты проб (слайдер на max, мобайл,
t=8 с) уходят критику вместе с обычными.

**Ассерты физики.** Из `spec.invariants` LLM-стадия `assertionWriter` пишет один JS-скрипт
`(smh) => [{id, pass, actual, expected}]`, использующий `getState/setParam/step`
(может прогнать `step(dt)` N раз без рендера). Скрипт запускается в странице с таймаутом
5 с; ошибка скрипта = «ассерт не применим» (не провал кандидата). Провал ассерта →
в отчёт фиксеру и критику как «инвариант I2 нарушен: ожидалось …, получено …».
В `fast` ассерты выключены.

**Критик** получает spec, ProbeReport, результаты ассертов и 6-8 кадров; отвечает
`{physicsOk, issues:[{severity:'blocker'|'major'|'minor', text, fixHint}]}`.
Блокеры и мажоры → **целевая починка** (`targetedFix`: рефайнер с промптом «исправь
именно это», один раунд) → повторные пробы. Так критик влияет на результат и в `fast`
(если vision настроен).

**Renderer.** `page.route` блокирует всё вне whitelist и `data:`; сборка кадров через
единый `session(html)` с методами `shot()`, `click(sel)`, `setSlider(name,v)`,
`evaluate()`; в отчёт добавляется `network:[…]`, `fps`, `mobileShot`. Таймаут CDN
отличается от зависания страницы («CDN недоступен: три попытки»).

Тесты: фикстуры `probe-*.html` (сломанный слайдер, не работающая пауза, NaN, статичный,
мобильное перекрытие) — каждая проба ловит свой случай; ассерт-скрипт на pendulum
(период) проходит, на «сломанной гравитации» — нет.

### 3.5 Надёжность генерации (`provider.ts`, `settings`, `types.ts`)

- `ProviderProfile.roles?: { planner?, generator?, fixer?, critic?, judge? : {model, temperature?, maxTokens?, extraBody?} }`; дефолт — текущие `generationModel`/`visionModel`.
- `max_tokens` по умолчанию 16000 для генератора/рефайнера/фиксера, 4000 для JSON-ролей;
  при `finish_reason === 'length'` — до 2 продолжений («продолжи ровно с места обрыва,
  без повторов») со склейкой; если после склейки нет `</html>` — кандидат провален с
  причиной `truncated`.
- Опциональный `response_format: {type:'json_object'}` для JSON-ролей, если провайдер
  поддерживает (флаг в профиле); иначе текущий `extractJson`.
- Телеметрия: событие `{type:'usage', role, model, promptTokens, completionTokens, ms}`
  на каждый вызов; агрегат в `quality.json` и в таймлайне UI («12 вызовов, 148k токенов,
  4 мин 12 с»).
- Streaming для генератора: прогресс «получено 12 КБ» в карточке кандидата (событие
  `candidate-progress`), без изменения контракта `ChatFn` наружу — внутри
  `chatWithClient` через `stream:true` с накоплением.

### 3.6 Судья 2.0 и доводка (`judge.ts`, `run.ts`, `prompts.ts`)

- Рубрика: `physics, clarity, interactivity, aesthetics, pedagogy (сценарий/цели/квиз),
  wow`. Итог = среднее LLM-оценок × коэффициент проб (`passRate`) − штраф за проваленные
  ассерты. Формула детерминирована и покрыта тестом; кандидат с проваленными пробами не
  побеждает у кандидата без провалов при разнице LLM-оценок < 1.5.
- Судья по-прежнему один вызов на всех, но получает ProbeReport и ассерты каждого.
- Рефайнер: единый блок `GENERATION_RULES` (лейаут, SimUI 2.0, CDN, dt-цикл) используется
  генератором, рефайнером и фиксером; рефайнер получает spec, замечания, 2-3 кадра и
  список проб; ответ — полный HTML (диффы не вводим — модели надёжнее переписывают).
- Стоп-правило доводки: порог `min ≥ 8` **или** улучшение итоговой оценки < 0.3 за круг
  **или** лимит кругов; каждый круг обязан пройти §3.4 (иначе откат к предыдущей версии).

### 3.7 Доводка как job, галерея, «сначала план» (`api`, `Workbench`, `progress/*`)

- `POST /api/simulations/[id]/refine` → `{jobId}`; job типа `refine` проходит
  рефайнер → пробы → критик (если есть) → сохранение; те же события/SSE/отмена. История
  инструкций (последние 5) хранится в `meta.refineLog` и подаётся рефайнеру как контекст.
- Галерея кандидатов: `GET /api/jobs/[id]/candidates/[index]` отдаёт HTML живого
  кандидата (job хранит html кандидатов в памяти до завершения + на диске в
  `data/jobs/<id>/cand-<i>.html`); CandidateCard получает кнопку «Открыть» (iframe в
  модалке) и «Выбрать этот» — событие `winner-override` → пайплайн доводит выбранного;
  после завершения job'а сохранённые кандидаты можно «Сохранить как отдельную симуляцию».
- Режим «Сначала план» — §3.2; UI: PlanCard становится редактируемой формой с кнопкой
  «Генерировать».
- `useJob()` хук выносится из `Workbench.tsx` (подключение, реплей, отмена, localStorage).

### 3.8 Evals 2.0 (`evals/`)

- Параллельность 2-3; режимы `fast|standard|max` параметром; оценка — по сохранённому
  `spec.json` (без повторного `plan()`); в отчёт: пробы passRate, ассерты, токены, время,
  стоимость (цена за 1k в профиле, опционально).
- Сравнение с предыдущим отчётом: дельта по рубрике и «регрессии» (промпты, где итог
  упал > 1.0).
- Чек-лист §2 как YAML-рубрика для судьи в evals (`evals/rubric.yaml`), чтобы «ДВС, но
  лучше» измерялся, а не декларировался.

## 7. Риски и решения

- **Промпт генератора растёт** (правила + doc кита + эталон 25 КБ ≈ 12-15k токенов
  входа). Приемлемо для качества; для «fast» эталон урезается до 12 КБ (первые секции).
- **Интроспекция не реализована моделью** (`SimUI.expose` пропущен) → пробы `reset/nan`
  и ассерты помечаются «не применимо», критик получает замечание, фиксер — требование
  добавить `expose`. Демо-гейт не пропускает эталон без `expose`.
- **Ассерт-скрипт неверен сам по себе** → ложный провал. Смягчение: ассерты влияют на
  оценку, но не убивают кандидата; в отчёте показываем `actual/expected`, преподаватель
  видит.
- **Ложные срабатывания проб** (например, симуляция, где на max слайдера картина
  действительно не меняется). Спецификация помечает такие параметры `visibleEffect:false`,
  проба их пропускает.
- **Провайдеры без `stream`/`response_format`/`max_tokens`** — флаги в профиле,
  деградация к текущему поведению.
- **three importmap** ломает артефакты, которые уже импортируют по полному URL —
  importmap не мешает абсолютным импортам; addons подключаются по `three/addons/…` только
  в новых генерациях.

## 8. Вне рамок

Мультиагентная генерация с tool-calling внутри одного вызова (зависит от провайдера;
пробы дают тот же эффект детерминированно), эмбеддинги для подбора эталонов, облако и
аккаунты, генерация видео, редактор кода артефакта в UI, локализация на другие языки.
