# Видимая B2B-часть: админка, кабинет организации, кабинет учителя, курсы ученика

**Дата:** 2026-09-18
**Статус:** к реализации (владелец прямо попросил эти экраны после проверки циклов 0–1)
**Карта:** `docs/superpowers/2026-09-16-b2b-platform-roadmap.md`, циклы 2, 3, 4a, 6 (сжато)
**Опирается на:** цикл 0 (`2026-09-17-org-access-model-design.md`) и цикл 1 (`2026-09-17-worker-queue-ops-design.md`), обе ветки готовы локально

## 1. Зачем и что входит

После циклов 0–1 организации и роли есть только в базе и в консольном скрипте. Владелец
зашёл в систему и не нашёл ни админки, ни кабинета учителя, ни курсов. Этот цикл делает
всё, что можно потрогать руками, и ведёт тест системы от начала до конца:

1. **Админ платформы** (`/admin`) создаёт школу и её администратора.
2. **Админ организации** (`/org`) заводит учителей, группы и массово учеников, печатает
   лист паролей.
3. **Учитель** (`/teach`) собирает курс: темы, блоки (текст, тренажёр из своей
   библиотеки или общего каталога, VR-лаборатория, задание), открывает его группам.
4. **Ученик** (`/learn`) видит курсы, проходит темы, отвечает на задания.
5. **Учитель** смотрит ответы, ставит оценку и комментарий, видит журнал.

**Не входит** (следующие волны, в карте они остаются): автопроверка по состоянию
симуляции (`sim_state`), задания с целью внутри VR-лабораторий (`lab_goal`), Прометей и
интересы, ИИ для учителя, приглашения ссылкой, коды групп, дедлайны с уведомлениями,
экспорт в Excel, копирование курса, соавторы.

**Инвариант.** Пользователь без членств видит продукт как раньше. Лаборатории открыты
всем, в том числе гостям.

## 2. Кто куда заходит

Навигация строится на сервере из членств (`navSections`). Новые разделы:

| Раздел | Путь | Кому виден |
|---|---|---|
| Курсы | `/learn` | есть членство `student` |
| Преподавание | `/teach` | есть членство `teacher` или `org_admin` |
| Организация | `/org` | есть членство `org_admin` |
| Админка | `/admin` | `users.role = 'admin'` |

Точное правило для «Курсы»: виден, если есть членство `student`. Учителю курсы видны в
«Преподавании» с кнопкой «Как видит ученик».

Если у человека членства в нескольких организациях, разделы `/org` и `/teach` показывают
переключатель организации вверху страницы (выбор хранится в адресе: `?org=<slug>`).

Главная страница после входа:
- ученик без права генерации → `/learn` (раньше вело в библиотеку);
- остальные — как сейчас.

Страница входа не меняется. Подсказка для теста: README получает раздел «Как проверить
B2B-часть» с пошаговым сценарием и командой `npm run seed:school`, которая заводит
тестовую школу (см. раздел 10).

Любой чужой или несуществующий объект в этих разделах — 404. Раздел без прав — 404.

## 3. Админка платформы `/admin`

Только `users.role = 'admin'`.

- **Обзор**: число организаций, пользователей, генераций за 7 дней, очередь сейчас
  (из `/api/health`-логики).
- **Организации**: таблица (название, тип, slug, участников, создана, архив).
  «Создать организацию»: название, тип, slug (подставляется транслитом из названия,
  правится), первый администратор — почта **или** логин и имя. Если аккаунт с такой
  почтой уже есть — он становится `org_admin`; если нет — создаётся с временным паролем,
  который показывается **один раз** в окне с кнопкой «Скопировать».
  Карточка организации: участники по ролям, группы, настройки (три переключателя
  из цикла 0), «В архив» / «Вернуть».
- **Пользователи**: поиск по почте, логину, имени; карточка: членства, дата создания,
  статус; действия: «Сбросить пароль» (временный пароль один раз на экране), «Заблокировать» /
  «Разблокировать», «Сделать админом платформы» / «Снять» (нельзя снять с себя).
- **Каталог**: список симуляций всех пользователей с поиском (название, автор), флажок
  «В общем каталоге». Каталог виден всем учителям при вставке тренажёра в курс.
- **Журнал**: последние 200 действий админов (кто, что, над чем, когда).

Каждое действие админки пишет строку в `admin_actions`.

## 4. Кабинет организации `/org`

Видит `org_admin` своей организации (и админ платформы через ссылку из админки).

- **Обзор**: название, тип, число учителей, учеников, групп, курсов.
- **Учителя**: таблица; «Добавить учителя»: почта **или** логин и имя. Существующий
  аккаунт по почте добавляется членством; новый создаётся с временным паролем (показ
  один раз). Действия: сбросить пароль, заблокировать, убрать из организации
  (членство удаляется, курсы остаются в организации, владельцем курса становится
  админ организации, который это сделал).
- **Группы**: таблица (название, учителя, учеников); создать, переименовать, в архив;
  карточка группы: ученики, учителя группы (назначить / снять).
- **Ученики группы — массово**: поле «Вставьте список: по одному человеку на строку,
  Фамилия Имя» или загрузка CSV (`Фамилия;Имя` или `Фамилия,Имя`, UTF-8). Предпросмотр:
  таблица с будущими логинами, пометки «дубль в списке», «пустая строка», «уже есть в
  группе». Кнопка «Создать N учеников». Логин: транслит `фамилия.и.slug`, при занятости —
  `фамилия.и2.slug` и т. д. Пароль — временный из трёх слов.
- **Лист паролей** `/org/groups/<id>/credentials`: карточки «ФИО / логин / пароль /
  адрес сайта» под печать (`@media print`, 8 карточек на A4). Пароли показываются только
  для учеников, которые **ещё не сменили** временный пароль; они хранятся для этого в
  открытом виде в отдельной таблице `pending_credentials` и удаляются при смене пароля.
  Это осознанный компромисс: без почты другой доставки нет. Строка живёт не дольше
  30 дней, после чего пароль можно только сбросить.
- **Ученики поштучно**: добавить одного, сбросить пароль (новая строка в листе),
  заблокировать, перевести в другую группу.
- **Настройки**: три переключателя цикла 0.

Учитель группы (не админ) может в своей группе: смотреть учеников, сбрасывать им пароль,
печатать лист. Создавать учеников и группы — только админ организации.

## 5. Кабинет учителя `/teach`

Видит `teacher` и `org_admin`.

### Курсы

- Список моих курсов в выбранной организации: название, предмет, статус
  (черновик / опубликован / архив), группы, число тем, «непроверенных ответов: N».
- «Новый курс»: название, предмет, описание.
- Карточка курса — **редактор**:
  - слева темы: добавить, переименовать, удалить (с подтверждением), порядок кнопками
    ↑/↓ (перетаскивание — позже);
  - справа блоки выбранной темы в порядке, у каждого ↑/↓, «Изменить», «Удалить»;
  - «Добавить блок»: Текст · Тренажёр · Лаборатория · Задание;
  - сверху: «Опубликовать» / «Снять с публикации», «Кому открыт» (выбор групп
    организации, в которых учитель ведёт занятия; админ организации — любые),
    «Как видит ученик» (открывает `/learn/...` в режиме просмотра).
  - изменения сохраняются сразу (каждое действие — запрос); индикатор «Сохранено».

### Блоки

| Тип | Что задаёт учитель | Что видит ученик |
|---|---|---|
| Текст | заголовок (необязательно), текст с простой разметкой: абзацы, `**жирный**`, `*курсив*`, списки `- `, заголовки `## `, ссылки | отформатированный текст |
| Тренажёр | симуляция из «Моя библиотека» или «Общий каталог» (диалог с поиском и превью), подпись | встроенная рамка симуляции + «На весь экран» |
| Лаборатория | одна из VR-сцен, подпись | карточка со встроенной сценой, «Открыть», QR для очков |
| Задание | см. ниже | форма ответа |

Разметка текста рендерится собственным маленьким безопасным преобразователем (экранирование
HTML, затем разрешённые конструкции). Новых зависимостей нет.

«Сгенерировать тренажёр для этого блока» — ссылка в мастерскую с `?returnTo=<блок>`;
после сохранения новой симуляции мастерская показывает «Вставить в урок», и симуляция
встаёт в блок. Квота — учителя.

### Задания

Задание — блок с полями: текст задания, тип, баллы (по умолчанию 10), «стенд»
(необязательно: тренажёр или лаборатория, показывается рядом с вопросом), разрешить
повторную сдачу (да/нет).

| Тип | Настройка | Проверка |
|---|---|---|
| `choice` | варианты (2–10), отмеченные правильные, один или несколько ответов | автоматически: полный балл при точном совпадении, иначе 0 |
| `number` | правильное число, допуск (абсолютный), единицы (подпись) | автоматически |
| `text` | — | вручную учителем |

Так «изучи тренажёр / лабораторию и ответь» — это `choice`, `number` или `text` со стендом.
«Смешай и получи вещество» с автопроверкой — следующая волна (`lab_goal`); пока его
оформляют как `text`/`choice` со стендом «Стол реакций».

**Правка задания после сдачи.** У блока есть `revision`; ответ запоминает ревизию.
Если учитель меняет правильный ответ, система предлагает «Пересчитать N сданных ответов».

### Ответы и журнал

- «Ответы» на задание: таблица ученик × статус (не начато / сдано / проверено / возвращено)
  × балл × дата; фильтр «Только непроверенные»; кнопки «Предыдущий» / «Следующий».
- Карточка ответа: вопрос, ответ ученика, автобалл (если есть), поле «Балл» и
  «Комментарий», кнопки «Поставить», «Вернуть на доработку».
- «Журнал» курса: ученики групп курса × задания, в клетке балл или статус; итог по
  ученику (сумма / максимум); «Скачать CSV».
- «Прогресс»: ученики × темы, отметка «открывал».

## 6. Раздел ученика `/learn`

- **Мои курсы**: карточки опубликованных курсов, открытых группам ученика; прогресс
  «тем открыто k из n», «заданий сдано k из m».
- **Курс**: список тем с отметками.
- **Тема**: блоки подряд. Задание: форма ответа, «Сохранить черновик» (автосохранение
  раз в 5 секунд для текста), «Сдать». После сдачи: статус, автобалл сразу для
  `choice`/`number` (правильный ответ не показывается), оценка и комментарий учителя
  после проверки; «Сдать заново», если учитель вернул или разрешил повтор.
- «Мои оценки»: задания × баллы по всем курсам.
- Экран рассчитан на телефон.

Ученик видит только опубликованные курсы своих групп. Скрытые правильные ответы не
уходят в браузер ученика никогда (сервер отдаёт задание без поля правильных ответов).

Симуляция в блоке курса открывается ученику по правилу `canView`: владелец, или
симуляция в каталоге, или она вставлена в опубликованный курс, открытый группе
пользователя. Правка и удаление — только владельцу. Если учитель удалил симуляцию,
блок показывает «Тренажёр удалён автором».

## 7. Данные: миграция `006_lms.sql`

```sql
CREATE TABLE admin_actions (
  id bigserial PRIMARY KEY, actor_id uuid REFERENCES users(id) ON DELETE SET NULL,
  action text NOT NULL, target text, payload jsonb NOT NULL DEFAULT '{}', at timestamptz NOT NULL DEFAULT now());

CREATE TABLE pending_credentials (
  user_id uuid PRIMARY KEY REFERENCES users(id) ON DELETE CASCADE,
  password text NOT NULL, created_at timestamptz NOT NULL DEFAULT now());

ALTER TABLE simulations ADD COLUMN visibility text NOT NULL DEFAULT 'private'
  CHECK (visibility IN ('private','catalog'));

CREATE TABLE courses (
  id uuid PRIMARY KEY, org_id uuid NOT NULL REFERENCES organizations(id) ON DELETE CASCADE,
  owner_id uuid NOT NULL REFERENCES users(id), title text NOT NULL, subject text NOT NULL DEFAULT '',
  description text NOT NULL DEFAULT '',
  status text NOT NULL DEFAULT 'draft' CHECK (status IN ('draft','published','archived')),
  created_at timestamptz NOT NULL DEFAULT now(), updated_at timestamptz NOT NULL DEFAULT now());
CREATE TABLE course_groups (
  course_id uuid REFERENCES courses(id) ON DELETE CASCADE,
  group_id uuid REFERENCES groups(id) ON DELETE CASCADE, PRIMARY KEY (course_id, group_id));
CREATE TABLE topics (
  id uuid PRIMARY KEY, course_id uuid NOT NULL REFERENCES courses(id) ON DELETE CASCADE,
  position int NOT NULL, title text NOT NULL);
CREATE TABLE blocks (
  id uuid PRIMARY KEY, topic_id uuid NOT NULL REFERENCES topics(id) ON DELETE CASCADE,
  position int NOT NULL, kind text NOT NULL CHECK (kind IN ('text','simulation','lab','assignment')),
  payload jsonb NOT NULL, revision int NOT NULL DEFAULT 1, updated_at timestamptz NOT NULL DEFAULT now());
CREATE TABLE topic_views (
  topic_id uuid REFERENCES topics(id) ON DELETE CASCADE, user_id uuid REFERENCES users(id) ON DELETE CASCADE,
  first_at timestamptz NOT NULL DEFAULT now(), last_at timestamptz NOT NULL DEFAULT now(),
  PRIMARY KEY (topic_id, user_id));
CREATE TABLE submissions (
  id uuid PRIMARY KEY, block_id uuid NOT NULL REFERENCES blocks(id) ON DELETE CASCADE,
  student_id uuid NOT NULL REFERENCES users(id) ON DELETE CASCADE, block_revision int NOT NULL,
  answer jsonb NOT NULL,
  status text NOT NULL CHECK (status IN ('draft','submitted','returned','graded')),
  auto_score numeric, score numeric, comment text,
  submitted_at timestamptz, graded_at timestamptz, graded_by uuid REFERENCES users(id),
  updated_at timestamptz NOT NULL DEFAULT now(), UNIQUE (block_id, student_id));
```

Одна строка ответа на ученика и задание: повторная сдача перезаписывает ответ и
сбрасывает оценку (история попыток — следующая волна).

Удаление членства учителя не удаляет его курсы: `owner_id` переписывается на того, кто
убрал учителя. Пользователей в организациях не удаляют — блокируют.

Модули (только Postgres, по образцу `src/lib/org/*`): `src/lib/admin/*`,
`src/lib/lms/{courses,blocks,submissions,grading,markup,access}.ts`. Чистая логика
(транслит и логины, разбор списка/CSV, проверка `choice`/`number`, разметка, сборка
журнала, санация payload блока, удаление правильных ответов из задания для ученика) —
отдельные модули без базы, покрытые юнитами.

## 8. API

Все роуты — под `/api/admin/*`, `/api/org/[slug]/*`, `/api/teach/*`, `/api/learn/*`.
Проверки доступа — в роуте через функции `src/lib/org/access.ts` и `src/lib/lms/access.ts`.
Тела проверяются (типы, длины: название ≤ 200, текст блока ≤ 20 000, вариант ≤ 500,
ответ `text` ≤ 10 000, список учеников ≤ 300 строк). Ошибки — русскими предложениями.
Чужое — 404.

## 9. Интерфейс

Существующая система (`globals.css`: панели, таблицы, сегменты, чипы, кнопки). Новые
иконки для разделов: «Курсы», «Преподавание», «Организация», «Админка». Таблицы на
телефоне превращаются в карточки. Пустые состояния объясняют, что делать дальше
(«Пока нет групп. Создайте первую — например, «7А».»).

## 10. Тестовый сценарий и сид

`npm run seed:school` (только если `NODE_ENV !== 'production'`): создаёт
- админа платформы `admin@local.test`;
- школу `sch12` «Школа №12» с админом `director@local.test`;
- учителя `teacher@local.test`, группу «7А» с тремя учениками;
- курс «Физика 7: механика» с двумя темами: текст, тренажёр из встроенных примеров
  (маятник), лаборатория «Оптический стол», задания `choice`, `number`, `text`;
- печатает все логины и пароли.

README: раздел «Как проверить B2B-часть» — по шагам от админа до журнала.

## 11. Тестирование

- Юниты: транслит/логины, разбор списка и CSV, проверка ответов, разметка (включая
  попытки XSS), сборка журнала, санация блоков, скрытие правильных ответов, навигация.
- Интеграционные (Postgres): доступ по ролям и 404 чужим на каждом новом роуте;
  массовое создание учеников; лист паролей исчезает после смены пароля; курс виден
  только группам; ответ сдаётся, автопроверка ставит балл, учитель ставит оценку;
  пересчёт после правки; ученик не получает правильные ответы; `canView` для
  симуляции из курса; удаление членства учителя переписывает владельца курсов.
- e2e: сценарий админ → организация → учитель → курс → ученик → ответ → оценка.

## 12. Приёмка

1. Весь сценарий раздела 10 проходится в браузере без консоли.
2. Гость открывает лаборатории; B2C-пользователь не видит новых разделов.
3. 30 учеников из списка создаются за один шаг; лист печатается.
4. Ученик не видит чужих курсов, черновиков и правильных ответов.
5. `npm test` (с базой и без), `tsc`, `build`, e2e зелёные.
