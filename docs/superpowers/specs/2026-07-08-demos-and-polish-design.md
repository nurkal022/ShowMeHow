# ShowMeHow: демо-библиотека + полировка системы — спецификация

**Дата:** 2026-07-08
**Статус:** утверждено

## 1. Цель

1. 10 вшитых образцовых демо-симуляций, устанавливаемых в библиотеку одной командой/кнопкой —
   работают без LLM-провайдера, задают планку качества и служат витриной.
2. Закрыть весь список отложенных улучшений из `docs/superpowers/2026-07-07-followups.md`.

## 2. Демо-симуляции

### 2.1 Хранение и установка

- Папка `demos/<slug>/` в репозитории: `artifact.html` (БЕЗ инжектированного runtime —
  инжектится при установке) + `meta.json` `{title, prompt, subject, tags}`.
- `src/lib/demos.ts`: `listBundledDemos(): DemoEntry[]`, `installDemos(): Promise<{installed: string[]; skipped: string[]}>` —
  для каждой демки: `createSimulation(meta+, instrument(html))`, thumbnail через `renderArtifact`.
- Идемпотентность: `SimulationMeta` получает опциональное поле `demo?: string` (slug);
  установка пропускает slug, уже присутствующий в библиотеке.
- CLI: `npm run seed` (`tsx scripts/seed-demos.ts`).
- UI: в пустой библиотеке кнопка **«Установить 10 примеров»** → `POST /api/demos/install` →
  перезагрузка списка. Кнопка видна только когда в библиотеке нет ни одной демки.

### 2.2 Гейт качества демок

Интеграционный тест `tests/integration/demos.test.ts`: для КАЖДОЙ `demos/*/artifact.html`:
`instrument()` → `renderArtifact()` → `ok === true`, `animated === true`, `errors === []`;
`meta.json` содержит непустые title/prompt/subject и tags-массив. Тест падает, если демок < 10
(после завершения всех демо-задач; до этого — проверяет имеющиеся).

### 2.3 Требования к каждой демке

Один самодостаточный HTML; только whitelist-CDN (three/p5/matter/chart/KaTeX — по необходимости);
SimUI для всех контролов (title + слайдеры + playPause, обязателен обработчик reset);
анимация через requestAnimationFrame с dt-шагом; русские подписи и единицы; формулы KaTeX,
где уместны; физика корректна и реагирует на слайдеры наглядно; 60 FPS на средней машине
(≤ ~2000 частиц, без утечек).

## 3. Улучшения системы

### 3.1 Качество пайплайна
- `verifyCandidate`: best-so-far — если попытка автопочинки регрессирует (был ok/статичный →
  стал !ok), вернуть лучшую предыдущую версию, не терять кандидата.
- CDN-скан: после генерации/фикса regex-скан внешних `src=`/`href=`; URL вне whitelist →
  ошибка в автопочинку (как JS-ошибка).
- Провайдер: не ретраить ошибки 400/401/403/404 (по `status` из ошибки openai SDK);
  429/5xx/сеть — ретраить как раньше.
- Рендерер: `browser.on('disconnected')` сбрасывает singleton (self-heal после смерти браузера).
- Промпт генератора: компактный few-shot «скелет образцовой симуляции» (~60 строк: структура,
  dt-цикл, SimUI-вызовы, reset) — добавляется в `generatorSystem`.

### 3.2 UX
- `PreviewFrame`: слушает `message` `{type:'sim-error'}` из iframe → ненавязчивая плашка-оверлей
  с текстом ошибки (закрываемая).
- История версий: подпись — локализованная дата/время (`ru`), не имя файла; после отката
  thumbnail обновляется (сервер делает это в POST history).
- `consumeSSE`: если поток закрылся без `done`/`error` → сообщение об ошибке, phase='error'.
- События кандидатов: судья работает с массивом alive — оркестратор мапит индексы обратно
  в исходные номера кандидатов в событии `scores` (UI показывает те же «Кандидат N», что и чипы).
- Карточка библиотеки: у thumbnail фиксированный aspect-ratio-плейсхолдер (нет мигания
  битой картинки).

### 3.3 API и код
- `export`/`DELETE`/`thumbnail`: невалидный/неизвестный id → 400/404 (не 500).
- `instrument()`: при отсутствии `<head>` вставлять runtime после `<html...>` (или после
  doctype, если нет и `<html>`), не до doctype.
- `loadSettings`: try/catch вокруг JSON.parse + поверхностная валидация формы (providers —
  массив, qualityMode ∈ {fast,standard,max}); битый файл → дефолты + console.warn.
- PUT `/api/settings`: маскированный ключ для id, которого нет в текущих настройках → 400.
- Мелочи: `evals/run.ts` — один `new Date()`; CSS `.provider`/`.radio` заскоупить под `.settings`;
  детерминированный тест коллизии истории (мок Date); тест ветки «фиксер бросил» в stages.
