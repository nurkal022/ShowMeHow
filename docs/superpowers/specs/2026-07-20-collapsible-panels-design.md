# Сворачиваемые непере­крывающие панели + улучшение генераций — спецификация

**Дата:** 2026-07-20
**Статус:** утверждено (дизайн)

## 1. Проблема и цель

Симуляции ShowMeHow — самодостаточные HTML-артефакты. Их информационные панели,
легенды и графики нарисованы как `position:fixed`-блоки по углам и **перекрывают
основную визуализацию**, которую генератор растягивает на всё окно. Панели нельзя
свернуть. На мобиле перекрытие критично.

**Цель:** каждая панель/легенда сворачивается одним кликом и не блокирует визуализацию
навсегда; на узком экране панели стартуют свёрнутыми. Это работает **и для новых
генераций, и ретроактивно для уже сохранённых симуляций** в библиотеке. Попутно —
улучшить генерации: правила лейаута/панелей/мобильности в промптах, надёжность
(уход от хрупких CDN вроде chart.js), визуальное качество.

### Что НЕ входит (граница)
- Ретроактивный слой чинит только **наложение и сворачивание** старых симуляций.
  Внутренние баги их кода (например ошибка `chart.js … export 'default'` в демо
  «маятник») **не** лечатся автоматически — правила надёжности действуют только для
  новых генераций.
- Правки контента отдельных демо-файлов в `demos/` — вне scope.
- Логика пайплайна (планировщик/кандидаты/суд/доводка), API jobs, хранилище как
  таковое — не меняются, кроме точечного read-path (Компонент 1) и промптов.

## 2. Ключевые факты кодовой базы (основание дизайна)

- `instrument()` (`src/lib/artifact.ts:76`) инжектит рантайм в `<head>` на **этапе
  генерации, до сохранения**; идемпотентен по маркеру `<!--showmehow-runtime-->`.
  Вызовы только на write-path (`stages.ts:31,39`, `run.ts:240`, `demos.ts:75`).
- Хранилище тупое: `getArtifact` (`storage.ts:43`) читает байты как есть; read-роуты
  (`api/simulations/[id]/route.ts:13`, `present/[id]/page.tsx`, `export`, `refine`,
  `history`) отдают сохранённый HTML дословно.
- **Вывод:** правка `UIKIT_CSS/JS` в `runtime.ts` НЕ влияет на уже сохранённые симы —
  их рантайм вморожен. Значит для ретроактивности нужен свежий рантайм на чтении.
- Панели в артефактах — в основном **рукописные** `position:fixed`-дивы (инфо/формула
  `left:12px;bottom:12px`, у «маятника» ещё `#chart-panel right:12px;top:12px`,
  сталкивается с SimUI), плюс одна панель SimUI (`.sim-panel`, `right:12px;top:12px`).
  ~1 SimUI на 1–2 рукописных.
- Промпты (`prompts.ts`): `EXAMPLE_SKELETON` хардкодит full-window canvas + fixed
  `#info` (строки 58–61); `UIKIT_DOC` говорит «canvas растягивай на всё окно» и что
  SimUI появляется справа-сверху. Никаких правил против наложения, сворачивания,
  мобильности рукописных панелей. `CRITIC_SYSTEM` лишь постфактум ловит «наложения».
- `runtime.ts` экспортит `HARNESS_JS`, `UIKIT_CSS`, `UIKIT_JS`, `UIKIT_DOC`.
  `artifact.ts` использует первые три; `prompts.ts` — только `UIKIT_DOC` (в
  `generatorSystem`).

## 3. Компонент 1 — Reinstrument-on-read (ретроактивный рантайм)

**Механизм:** свежий рантайм применяется на **чтении**, а не только на генерации.

- Инжект оборачивается разделителями: `<!--smh-rt-start--> … <!--smh-rt-end-->`
  (вместо одиночного маркера) для надёжного удаления.
- `stripRuntime(html)`:
  1. Убирает новый блок: `/<!--smh-rt-start-->[\s\S]*?<!--smh-rt-end-->/g`.
  2. Убирает **легаси**-блок: `<!--showmehow-runtime-->` + ровно наши три тега
     (`<script>…</script><style>…</style><script>…</script>` без атрибутов), regex
     заякорен на маркер, поэтому чужие скрипты не заденет.
- `reinstrument(html) = instrument(stripRuntime(html))`.
- `instrument()` сохраняет идемпотентность по новому маркеру.

**Где применяется `reinstrument`:**
- Рендер-роуты, отдающие HTML для показа/скачивания: `api/simulations/[id]` (превью),
  `present/[id]` (презентация), `export` (self-contained). Экспорт остаётся
  запускаемым офлайн, т.к. рантайм внутри.
- **Refine / history-restore:** модели в качестве базы отдаём `stripRuntime(html)`
  (raw, без рантайма) — модель не видит служебный код и не дрейфит его.

**Стор не меняем:** новые симы по-прежнему сохраняются инжектированными (пайплайн не
трогаем); на чтении `reinstrument` для них — почти no-op (тот же текущий рантайм).
Старые — апгрейдятся прозрачно. Будущие правки рантайма тоже станут ретроактивными.

**Тесты (unit, `artifact.test.ts`):** raw→instrument содержит ровно один блок между
разделителями; instrument идемпотентен; `stripRuntime` снимает и новый, и легаси-блок;
`reinstrument(reinstrument(x)) === reinstrument(x)`; чужой `<script src=…>` артефакта
переживает strip.

## 4. Компонент 2 — Универсальный слой сворачивания (`UIKIT_JS`/`UIKIT_CSS`)

Скрипт в рантайме, выполняется после загрузки артефакта; `MutationObserver` ловит
панели, созданные позже (в т.ч. самим SimUI).

**Детекция панели (для легаси-симов, эвристика):** элемент с
`getComputedStyle(el).position === 'fixed'`, который: не `<canvas>`; не служебный
(SimUI toggle/close); имеет текст/детей; занимает не более ~60% площади вьюпорта
(отсекаем сцену/оверлеи). Каждой такой панели вешаем шеврон-кнопку.

**Поведение:**
- Инжектим кнопку `.smh-collapse-btn` (▾/▸) абсолютом в верх-правый угол панели.
- Клик → тоггл класса `smh-collapsed` на панели.
- CSS: `.smh-collapsed > *:not(.smh-collapse-btn){display:none!important}` +
  схлопывание паддинга/ширины до компактной плашки (виден только шеврон, опц. иконка).
- На `≤640px` панели инициализируются со `smh-collapsed`.
- Идемпотентность: панель, уже помеченная `data-smh-panel`, повторно не обрабатывается
  (важно из-за MutationObserver и React-strict реплея не касается — это внутри iframe).

**SimUI-панель** получает тот же шеврон и на десктопе (единый паттерн «свернуть всё»);
мобильный bottom-sheet из прошлого релиза сохраняется.

**ES5-совместимость** (крутится сырьём в артефакте): `var`, без стрелок/`const`,
`classList.add/remove`, `addEventListener`.

**Reduced-motion:** переходы сворачивания под общий guard (мгновенно, без анимации).

## 5. Компонент 3 — `SimUI.panel()` для новых генераций

Новый метод фабрики SimUI (существующие `title/slider/playPause` без изменений):

```
SimUI.panel({ title, corner })  // corner: 'tl'|'tr'|'bl'|'br' (по умолч. 'bl')
  → возвращает DOM-элемент (контент-контейнер), который модель наполняет
    произвольным содержимым: легенда, canvas-график, инфо-величины.
```
- Панель докируется в указанный угол, не по центру; сворачиваема тем же механизмом
  (Компонент 2); на мобиле стартует свёрнутой.
- Несколько панелей в одном углу стекируются вертикально без перекрытия.
- Слайдеры/`playPause` по-прежнему живут в основной `.sim-panel` (угол 'tr').

## 6. Компонент 4 — Промпты и генерация (`prompts.ts`, `UIKIT_DOC`)

- **Лейаут/панели:** запрет рукописных `position:fixed`-панелей; всё инфо/легенды/
  графики — только через `SimUI.panel`. Правило: центр экрана — под визуализацию;
  панели докируются по углам и **обязаны быть сворачиваемыми**; на мобиле свёрнуты.
- **Skeleton:** `EXAMPLE_SKELETON` переписать — вместо fixed `#info` показать
  `SimUI.panel` c инфо-величинами и (при нужде) canvas-легендой.
- **Надёжность:** предпочитать графики, рисуемые на `<canvas>` вручную (как в
  большинстве демо), а не внешние либы; CDN — только whitelist; явно предупредить о
  ловушке UMD/module default-export (причина ошибки chart.js в «маятнике»).
- **Визуальное качество:** дефолты SimUI (типографика, контраст, отступы) + краткие
  правила читаемости в промпте; `UIKIT_DOC` описывает `SimUI.panel` и правило углов.

## 7. Тестирование и приёмка

- **Unit:** `artifact.test.ts` — сценарии из §3.
- **Демо-гейт (integration, `demos.test.ts`):** каждая демка через `instrument`
  (как сейчас) рендерится ok + animated + 0 ошибок; добавить проверку, что после
  рантайма у панелей появились `.smh-collapse-btn` и сворачивание не роняет рендер.
- **Визуально (скриншоты, headless, 1280×800 и 390×844):**
  1. Существующее демо «маятник» через `reinstrument` — на десктопе шевроны у панелей,
     клик сворачивает; на мобиле панели свёрнуты; центр не перекрыт.
  2. Мини-артефакт, использующий `SimUI.panel`, — панель докнута в угол, сворачивается,
     на мобиле свёрнута.
- **Гейты:** `npm test && npx tsc --noEmit && npm run build`. Только представление/
  рантайм/промпты — логика пайплайна не меняется.
- **Существующие тесты** (демо-гейт, derive, jobs и пр.) остаются зелёными.

## 8. Риски

- Эвристика детекции панелей может дать ложное срабатывание на нестандартном
  fixed-оверлее. Митигация: отсечка >60% площади, пропуск canvas/пустых, флаг
  `data-smh-panel` от повторной обработки. Демо-гейт ловит регрессии рендера.
- Регэксп-strip легаси-блока предполагает наши теги без атрибутов и якорь на маркер.
  Митигация: unit-тесты на реальных сохранённых файлах из `data/simulations` +
  демо-гейт. При промахе strip легаси-рантайм остался бы рядом с новым (конфликт
  `window.SimUI`), поэтому корректность strip проверяется тестом на каждом формате
  инжекта, встречающемся в сторе.
