# ShowMeHow — конструктор промпта: спецификация

**Дата:** 2026-09-06
**Статус:** утверждено, к реализации
**Основание:** пустое поле ввода — главный барьер для преподавателя, которому трудно
сформулировать запрос к модели

## 1. Задача

Сейчас единственный вход в продукт — пустая `textarea`. Человек, который не знает, что
и как писать, упирается в неё и уходит. Конструктор даёт второй путь: четыре шага выбора,
из которых собирается готовый промпт.

Конструктор **не заменяет** текстовый ввод и не добавляет серверной механики. Это форма,
которая пишет текст за пользователя и отправляет его в существующий пайплайн через тот же
`POST /api/generate`.

## 2. Экран

В мастерской над композером появляется переключатель на два положения:
**«Конструктор»** и **«Свой текст»**. По умолчанию открыт «Свой текст» — конструктор
равноправная альтернатива, а не обязательный путь.

Когда открыта существующая симуляция (режим доводки), переключателя нет: доводка всегда
текстовая.

### Шаг 1 — раздел и явление

Шесть разделов плиткой. Выбор раздела раскрывает список типовых явлений этого раздела
и поле «своё явление» на случай, если нужного нет.

| Раздел | Явления |
|---|---|
| Механика | маятник, свободное падение, движение по наклонной плоскости, столкновение шаров, вращение и центробежная сила, пружинный осциллятор |
| Оптика | преломление луча, отражение и зеркала, линза и построение изображения, дисперсия в призме, интерференция, дифракция на щели |
| Термодинамика | теплопередача, цикл Карно, расширение газа, фазовый переход, конвекция, теплопроводность стержня |
| Электричество и магнетизм | поле точечных зарядов, конденсатор, ток в цепи, магнитное поле проводника, электромагнитная индукция, сила Лоренца |
| Молекулярная физика | диффузия, броуновское движение, идеальный газ, осмос, испарение, распределение скоростей |
| Астрономия | орбита спутника, законы Кеплера, фазы Луны, солнечное затмение, приливы, чёрная дыра и гравитационная линза |

### Шаг 2 — как показать

Режим: **2D** или **3D**.

Стиль подачи, ровно три варианта:

| Стиль | Что означает для генератора |
|---|---|
| Схема | векторы, оси, подписанные обозначения, вид как в учебнике; минимум декора |
| Реалистично | объекты похожи на настоящие: материалы, тени, пропорции |
| Данные | упор на графики и числовые показания, картинка второстепенна |

### Шаг 3 — чем управлять

Чекбоксы параметров; набор зависит от выбранного раздела (для механики — масса, длина,
угол, начальная скорость, коэффициент трения, жёсткость пружины; для термодинамики —
температура, давление, объём, теплоёмкость и так далее). Отдельный пункт
**«предложи сам»** — тогда параметры выбирает планировщик.

### Шаг 4 — для кого

Три варианта: **7-9 класс**, **10-11 класс**, **студенты**. Влияет на глубину формул и
терминологию.

### Итог

Под шагами — предпросмотр собранного промпта обычным текстом, чтобы человек видел, что
именно уйдёт модели. Две кнопки:

- **«Создать»** — отправляет собранный текст в генерацию;
- **«Доработать текст»** — переключает на «Свой текст» с уже подставленным промптом.

## 3. Внутреннее устройство

Вся логика — одна чистая функция и одна таблица данных.

```ts
export type Style = 'schematic' | 'realistic' | 'data';
export type Level = 'grade7to9' | 'grade10to11' | 'students';

export interface ConstructorDraft {
  section: string;          // ключ раздела
  phenomenon: string;       // выбранное явление или своя формулировка
  mode: '2d' | '3d';
  style: Style;
  parameters: string[];     // выбранные параметры; пустой массив = «предложи сам»
  level: Level;
}

export function buildPrompt(draft: ConstructorDraft): string;
export function isComplete(draft: Partial<ConstructorDraft>): boolean;
```

`buildPrompt` собирает связный русский текст, а не список полей: сначала явление, затем
требование к режиму и стилю, затем перечисление управляемых величин, затем аудитория.
Промпт обязан читаться как поручение, написанное человеком, — планировщик получает его
на вход наравне с текстом, набранным вручную.

Таблица разделов, явлений и параметров лежит отдельным модулем данных, чтобы пополняться
без правки логики.

## 4. Тестирование

Покрывается юнит-тестами (библиотеки для рендера React-компонентов в проекте нет и
вводить её не будем):

- `buildPrompt` включает выбранное явление, режим, стиль и уровень;
- выбранные параметры перечислены в тексте; пустой список даёт формулировку «подбери
  параметры сам», а не пустое перечисление;
- своё явление, введённое руками, попадает в текст дословно;
- `isComplete` требует раздел, явление, режим, стиль и уровень, но не требует параметров;
- таблица данных согласована: у каждого раздела непустые списки явлений и параметров,
  ключи разделов уникальны.

## 5. Вне рамок

Сохранение черновиков конструктора между сессиями; конструктор для доводки существующей
симуляции; загрузка картинки из конструктора; предпросмотр результата до генерации.

## 6. Критерии приёмки

1. В мастерской виден переключатель «Конструктор | Свой текст»; по умолчанию открыт «Свой текст».
2. Все четыре шага проходятся, и до заполнения обязательных полей кнопка «Создать» недоступна.
3. Предпросмотр показывает ровно тот текст, который уйдёт в генерацию.
4. «Доработать текст» переносит собранный промпт в текстовое поле и переключает режим.
5. Выбор «предложи сам» даёт промпт без перечисления параметров, но с явной просьбой подобрать их.
6. При открытой симуляции переключателя нет — доводка остаётся текстовой.
7. `npm test`, `npx tsc --noEmit` и `npm run build` зелёные.
