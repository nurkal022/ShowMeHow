# ShowMeHow — дизайн-спецификация

**Дата:** 2026-07-07
**Статус:** утверждено, готово к планированию реализации

## 1. Цель

Инструмент для преподавателей: по текстовому промпту (опционально + картинка) генерирует
интерактивные научные визуализации и симуляции, которые можно показывать студентам на
занятиях. Примеры запросов: «диффузия молекул духов в комнате», «циркуляция тёплого
воздуха в комнате», «как работает двигатель внутреннего сгорания».

Приоритет проекта — **максимальное качество результата** (физическая корректность,
наглядность, эстетика), а не скорость или дешевизна генерации.

Референсы: Claude Artifacts, CUYO 3D Science Lab, Simulate It Now, MySimulator.

## 2. Ключевые решения

| Решение | Выбор |
|---|---|
| Способ создания симуляций | Свободная генерация кода LLM (артефакт-подход), не библиотека шаблонов |
| Масштаб MVP | Локальный инструмент, без аккаунтов и облака |
| Возможности симуляций | 2D и 3D сразу (белый список CDN-библиотек) |
| Стек | Next.js (App Router) + TypeScript, фуллстек |
| LLM-доступ | `openai` npm SDK с настраиваемым baseURL — любой OpenAI-совместимый провайдер |
| Пайплайн генерации | Агентный мультишаг: планировщик → N кандидатов → верификация → судья → доводка |
| Верификация | Headless-рендер на сервере (Playwright): ошибки JS, скриншоты, физик-критик (vision LLM) |

## 3. Архитектура

Локальное Next.js-приложение (запуск: `npm run dev` или Docker), открывается в браузере.

```
┌─────────────────────────────────────────────────┐
│  Next.js app                                    │
│                                                 │
│  UI (React)                 Server (API routes) │
│  ┌───────────────┐          ┌────────────────┐  │
│  │ Чат + превью  │◄──SSE────│ Пайплайн       │  │
│  │ (iframe-      │          │ генерации      │  │
│  │  sandbox)     │──errors─►│ (агентный)     │  │
│  ├───────────────┤          ├────────────────┤  │
│  │ Библиотека    │          │ Провайдер-слой │  │
│  │ симуляций     │          │ (openai SDK)   │  │
│  ├───────────────┤          ├────────────────┤  │
│  │ Настройки     │          │ Headless-      │  │
│  └───────────────┘          │ рендерер       │  │
│                             │ (Playwright)   │  │
│                             └────────────────┘  │
│  Хранение: ./data/ (файлы, без БД)              │
└─────────────────────────────────────────────────┘
```

### 3.1 Артефакт

Единица результата — **один самодостаточный HTML-файл**: весь JS/CSS внутри, разрешён
белый список CDN-библиотек:

- **three.js** — 3D-сцены (двигатель, молекулярные модели)
- **p5.js** — 2D-анимации и частицы
- **matter.js** — 2D-физика (столкновения, гравитация)
- **chart.js** — живые графики величин
- **KaTeX** — формулы

Артефакт можно рендерить в iframe, сохранять, экспортировать как файл и открывать
на любом компьютере без доступа к нашему серверу.

### 3.2 Sandbox-контракт

Артефакт исполняется в `<iframe sandbox="allow-scripts">` (и в headless-Chromium на
сервере). В артефакт автоматически инжектится runtime-скрипт (LLM его не пишет),
который по `postMessage`:

- сообщает приложению об ошибках JS (window.onerror, unhandledrejection);
- отдаёт скриншоты canvas по запросу;
- принимает команды: пауза / пуск / сброс.

### 3.3 UI-kit для артефактов

Встраиваемый набор стилей и готовых контролов: слайдеры параметров, кнопки
пуск/пауза/скорость, панель параметров, подписи формул (KaTeX). LLM использует эти
компоненты вместо изобретения интерфейса — единообразный профессиональный вид всех
симуляций. Физику и визуализацию LLM пишет свободно.

### 3.4 Провайдер-слой

Тонкая обёртка над `openai` npm SDK. В настройках — профили провайдеров:
имя, baseURL, apiKey, модель генерации, vision-модель для критики (может совпадать).
Поддерживаются OpenAI, OpenRouter, локальный Ollama и любой совместимый эндпоинт.
Ключи API живут только на сервере (`data/settings.json`), никогда не попадают в
клиентский код и артефакты.

### 3.5 Headless-рендерер

Playwright + Chromium на сервере. Для каждого кандидата:

- загружает артефакт, собирает ошибки консоли;
- проверяет, что canvas рисуется и анимация идёт (серия скриншотов t≈0s, 1s, 3s);
- таймаут 15 сек — зависший артефакт считается ошибочным.

## 4. Пайплайн генерации

```
Промпт (+картинка)
   ▼
① ПЛАНИРОВЩИК — педагогическая спецификация: что показываем, физические
   законы/уравнения, параметры для интерактива, что должен понять студент,
   план визуализации.
   ▼
② ГЕНЕРАЦИЯ N КАНДИДАТОВ (параллельно) — полные HTML-артефакты по
   спецификации с разными акцентами (реализм / наглядность / интерактив).
   ▼
③ ВЕРИФИКАЦИЯ каждого (параллельно):
   headless-рендер → при ошибках автопочинка (до 2 попыток) → скриншоты →
   ФИЗИК-КРИТИК (vision LLM): корректность физики против спецификации,
   единицы измерения, граничные условия.
   ▼
④ СУДЬЯ (vision LLM) — сравнивает кандидатов по скриншотам и отчётам критиков.
   Рубрика: физическая корректность / наглядность / интерактивность / эстетика.
   ▼
⑤ ЦИКЛ ДОВОДКИ — замечания → рефайнер правит код → рендер и повторная оценка.
   Судья ставит оценки 1-10 по каждому пункту рубрики; порог качества —
   все пункты ≥ 8. Лимит — 3 круга доводки, дальше отдаём лучшее из достигнутого.
   ▼
Готовый артефакт → превью + библиотека
```

### 4.1 Режимы качества

| Режим | Кандидаты | Судья/доводка | Время |
|---|---|---|---|
| Быстрый | 1 | нет | ~30-60 сек |
| Стандарт | 2 | 1 круг | ~1-3 мин |
| **Максимум (по умолчанию)** | 3 | до порога качества | ~3-6 мин |

Прогресс всех этапов стримится в UI по SSE в реальном времени.

### 4.2 Доработка через чат

После генерации пользователь итерирует в чате («сделай частицы медленнее», «добавь
график температуры»). Это короткий путь: правка кода текущего артефакта →
headless-проверка → отдача. Полный пайплайн не перезапускается. Каждая правка
сохраняется в историю версий с возможностью отката.

### 4.3 Eval-набор

Папка `evals/`: ~15 эталонных промптов (диффузия, конвекция, ДВС, маятник, волны,
оптика...). Прогон одной командой, судья-LLM ставит оценки по рубрике — регрессия
качества после изменения промптов видна сразу.

## 5. Модель данных

Всё — файлы в `./data/`, без БД:

```
data/
├── settings.json          # профили провайдеров, режим качества
└── simulations/<id>/
    ├── artifact.html      # текущая версия
    ├── meta.json          # название, промпт, дата, теги, предмет
    ├── history/           # прошлые версии (откат)
    └── thumbnail.png      # превью для карточки библиотеки
evals/                     # эталонные промпты и результаты прогонов
```

## 6. UI

- **Главный экран:** чат слева, превью артефакта (sandbox-iframe) справа; живой
  прогресс пайплайна; выбор режима качества.
- **Библиотека:** карточки с превью, поиск/теги, открытие, удаление, экспорт
  standalone-HTML.
- **Режим презентации:** полноэкранный показ симуляции для занятия.
- **Настройки:** профили провайдеров, выбор моделей.
- **Вход:** текстовый промпт + опциональная загрузка картинки (vision).

## 7. Обработка ошибок

- **Провайдер упал / таймаут** — 3 ретрая с экспоненциальной паузой; затем понятное
  сообщение с указанием этапа. Частичный результат сохраняется (2 из 3 кандидатов
  готовы — судим их).
- **Кандидат не чинится** (2 автопочинки не помогли) — выбывает. Выбыли все —
  показывается лучший «сломанный» с объяснением и кнопкой повтора.
- **Vision-модель недоступна** — деградация: пайплайн без визуальной критики
  (только проверка ошибок JS), предупреждение в UI.
- **Зависший артефакт** — таймаут headless-рендера 15 сек, кандидат ошибочен.
- **Безопасность:** ключи API — только на сервере; артефакты — только в sandbox.

## 8. Тестирование

- **Юнит:** оркестрация пайплайна с мок-LLM — ретраи, выбывание кандидатов,
  деградация без vision.
- **Интеграция:** headless-рендерер на заготовленных артефактах
  (рабочий / с JS-ошибкой / зависающий).
- **E2E-смоук (Playwright):** открыть приложение → сгенерировать с мок-провайдером
  → увидеть превью.
- **Качество генерации** — eval-набором (4.3), не тестами.

## 9. Вне рамок MVP

Аккаунты и облачный шаринг, мобильная версия, интеграция с LMS, генерация
видео/слайдов, библиотека шаблонов. Экспорт standalone-HTML — **в** MVP.
