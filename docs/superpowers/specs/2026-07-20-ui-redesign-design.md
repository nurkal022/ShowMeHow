# ShowMeHow: редизайн UI/UX (светлая тема, мобильный, анимированный прогресс) — спецификация

**Дата:** 2026-07-20
**Статус:** утверждено

## 1. Цель

Юзер-френдли редизайн: светлая образовательная дизайн-система, удобство на телефоне
(вкладки Создать/Превью, адаптив всех экранов), мобильный SimUI, анимированный
процесс генерации с конкретными пошаговыми описаниями. Только представление —
логика пайплайна/API/job не меняется.

## 2. Дизайн-система (светлая тема)

`src/app/globals.css` переписывается на токены:
- Палитра: `--bg:#f6f7f9`, `--surface:#ffffff`, `--surface-2:#f0f2f5`, `--border:#e3e7ec`,
  `--text:#161c26`, `--muted:#5b6675`, `--accent:#4f46e5` (+`--accent-hover:#4338ca`,
  `--accent-soft:#eef0fe`), `--success:#0f9d58`, `--danger:#e5484d`, `--warn:#d98324`.
  Тени: `--shadow-sm/-md` мягкие. Радиусы: `--r-sm:8px --r:12px --r-lg:16px`.
- Типографика: base 16px, system-ui; заголовки с чёткой иерархией; `line-height:1.5`.
- Базовые классы: `.btn`(`.btn-primary/.btn-secondary/.btn-ghost/.btn-danger`, min-height 44px),
  `.input`,`.select`,`.field`, `.card`, `.chip`, `.badge`, `.icon-btn`, состояния
  hover/disabled/focus-visible (кольцо `--accent`).
- **Тёмная тема НЕ обязательна** (выбран светлый вариант); переключатель — вне scope.

## 3. Навигация / шапка

`src/app/layout.tsx` + стили: шапка со светлым фоном, иконка-лого + «ShowMeHow»,
ссылки Создать/Библиотека/Настройки, активная подсвечена (по pathname — сделать
маленький клиентский `NavLinks`-компонент, т.к. layout серверный). На узком экране —
компактная строка, тач-цели ≥44px, горизонтальный скролл ссылок при нехватке ширины.

## 4. Главный экран (Workbench) — адаптив

- Десктоп (≥900px): текущая раскладка (чат-панель + превью), переоформленная под
  светлую систему; композер снизу крупный.
- Мобильный (<900px): **сегмент-вкладки** сверху «✏️ Создать» и «▶️ Превью»
  (клиентское состояние `activeTab`). Активная вкладка показывает свою колонку на весь
  экран. По событию `done` (симуляция готова) — автопереключение на «Превью».
  Композер — sticky снизу во вкладке «Создать». Кнопки/селекты крупные.
- Превью-iframe: всегда `width:100%`, высота — доступная область; на телефоне — почти
  весь экран во вкладке «Превью».
- Индикатор недоступности: если генерация идёт, а пользователь на «Превью» — маленький
  бейдж «идёт генерация» ведёт назад на «Создать».

## 5. Библиотека / Настройки / Презентация

- Библиотека: сетка `repeat(auto-fill, minmax(260px,1fr))` → на телефоне 1 колонка;
  карточки со светлым оформлением, крупные миниатюры (`.card-thumb` уже есть),
  поиск-инпут на всю ширину сверху, действия — иконки-кнопки; пустое состояние с
  заметной primary-кнопкой установки демо.
- Настройки: один столбец, карточки провайдеров `.card`, поля `.field`/`.input`,
  адаптив на телефоне (поля на всю ширину).
- Презентация (`/present/[id]`): фуллскрин-iframe остаётся; добавить полупрозрачную
  кнопку «← Выйти» в углу (ссылка на `/library`), скрывается/не мешает.

## 6. Анимированный прогресс с описаниями

Компоненты `src/components/progress/*` + `deriveProgress.ts`:
- **Микро-описания** (модуль `src/components/progress/stepCopy.ts`): функции, дающие
  русский текст по стадии/статусу кандидата/кругу доводки. Тексты из дизайна (§раздел
  «5» брифа): планирование, генерация варианта N, рендер, автопочинка, критика, суд,
  доводка (круг k), сохранение. Плюс подпись стиля кандидата (STYLE_NAMES).
- **StageTimeline:** активный чип пульсирует (CSS `@keyframes`), завершённый —
  галочка с «pop»-анимацией + длительность; тонкая полоса-прогресс по этапам сверху с
  «бегущим» shimmer на активной зоне.
- **CandidateCard:** появление карточки (fade+slide up), скриншот fade-in при смене,
  бары рубрики заполняются по ширине с transition, корона победителя — «pop».
  Статус-строка показывает текущее микро-описание.
- **PlanCard:** появляется fade-in после `plan-ready`.
- **RefinePanel:** круги доводки с микротекстом; смена min-оценки «before→after».
- **Reduced motion:** всё под `@media (prefers-reduced-motion: reduce)` отключается
  (мгновенные состояния без пульса/шиммера).
- Данные не меняются — только текст-слой и CSS. Логика deriveProgress остаётся; при
  необходимости добавляются производные поля (текущее описание), покрытые юнит-тестом.

## 7. Мобильный SimUI (runtime)

`src/lib/runtime.ts` `UIKIT_CSS`/`UIKIT_JS`:
- Панель `.sim-panel` на узком экране (`@media max-width:640px`) — сворачивается в
  кнопку-таблетку «⚙ Параметры» внизу; тап разворачивает панель снизу (bottom-sheet),
  повторный тап/крестик — сворачивает. На широком — как сейчас (справа сверху).
- Слайдеры крупнее (тач-цель), кнопки playPause крупнее.
- **Каглет:** меняет инжектируемый runtime → применяется к НОВЫМ генерациям и после
  переустановки демок. На сервере демки переустановить (re-seed).
- SimUI JS-API (`title/slider/playPause`) не меняется — только вёрстка/CSS панели +
  логика сворачивания.

## 8. Тестирование

- Юнит: `stepCopy` (тексты по стадиям/статусам — стабильные, не пустые); при добавлении
  производного «описания» в deriveProgress — тест на него; существующие тесты
  progress/derive не ломаются.
- UI-задачи: `npx tsc --noEmit && npm run build` + dev-smoke (curl 200) + визуальная
  проверка через headless-скриншоты в двух вьюпортах (desktop 1280 и mobile 390) для
  главной, библиотеки, настроек, и живого прогресса (мок-провайдер или существующая
  демка в превью). SimUI-мобайл — скриншот демо-артефакта в узком вьюпорте.
- Гейты прежние.

## 9. Вне рамок

Тёмная тема/переключатель; редизайн самих демок (только их SimUI-обёртка через runtime);
новая информационная архитектура/страницы; i18n. Логика пайплайна/API/jobs.
