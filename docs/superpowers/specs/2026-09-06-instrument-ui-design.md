# ShowMeHow — интерфейс «научный прибор»: спецификация

**Дата:** 2026-09-06
**Статус:** утверждено, к реализации
**Основание:** ветка `accounts-foundation` завершена; продукт получил аккаунты, но не получил лица

## 1. Задача

Интерфейс работает и не мешает, но он безлик: индиго на белом — оформление по умолчанию
любого дашборда. Ничто на экране не говорит, что это инструмент про физику и про показ
явления на занятии.

Есть и предметное противоречие: **симуляции тёмные** (кит рисует на `#101318`), а
приложение вокруг них светлое, поэтому каждое превью выглядит дырой в белом листе.

Задача — дать интерфейсу характер научного прибора и пересобрать экраны так, чтобы
на них было что делать, а не только на что смотреть.

### Рамки

| В рамках | Вне рамок |
|---|---|
| Тёмная тема и токены | Светлая тема и переключатель тем |
| Приведение примитивов к одному набору классов | Кит внутри симуляций (`src/lib/runtime/*`) |
| Пересборка четырёх экранов: вход, мастерская, галерея, презентация | Демки в `demos/` и промпт генератора |
| Онбординг из трёх шагов | Новые возможности продукта (папки, теги, история чата) |

Отдельно: **светлой темы не будет.** Переключатель удваивает проверку каждого экрана и
для поставленной задачи не даёт ничего.

**Принятый риск:** тёмный интерфейс хуже читается с проектора в светлой аудитории. На
проекторе показывают режим презентации, где весь экран занимает симуляция, а она тёмная
и без того; интерфейс преподаватель видит на своём ноутбуке.

## 2. Тема

### Токены

Заменяют текущий светлый набор в `:root` (`src/app/globals.css`). Имена сохраняются —
меняются значения, поэтому ни одно существующее правило не ломается.

| Токен | Значение | Назначение |
|---|---|---|
| `--bg` | `#0d1117` | фон приложения |
| `--surface` | `#151b24` | панели, карточки |
| `--surface-2` | `#1c232e` | вложенные поверхности, дорожки шкал |
| `--border` | `#28313d` | границы |
| `--text` | `#e6edf3` | основной текст |
| `--muted` | `#8b98a9` | подписи, второстепенное |
| `--accent` | `#22d3ee` | акцент интерфейса |
| `--accent-hover` | `#67e8f9` | наведение |
| `--accent-soft` | `#12313a` | подложка активного состояния |
| `--success` | `#3fb950` | успех |
| `--danger` | `#f85149` | ошибка |
| `--danger-soft` | `#2d1618` | подложка ошибки |
| `--warn` | `#d29922` | предупреждение |
| `--warn-soft` | `#2b2113` | подложка предупреждения |
| `--grid-line` | `rgba(120,140,170,.05)` | линия фоновой сетки |

Акцент — циан, намеренно не тот синий (`#4f8ff7`), которым рисуют сами симуляции:
интерфейс не должен спорить с содержимым.

Тени на тёмном фоне почти не читаются, поэтому `--shadow-sm` и `--shadow-md`
переопределяются на более глубокие и дополняются светлой внутренней границей сверху
(`inset 0 1px 0 rgba(255,255,255,.03)`) — на тёмном именно она создаёт объём.

### Сетка

Фон приложения несёт **очень тонкую миллиметровку**: два повторяющихся линейных
градиента с шагом 32 px цветом `--grid-line`. Никаких изображений. Сетка — единственный
элемент, который делает всю работу по характеру «прибора»; она обязана быть на грани
различимости, иначе превращается в шум.

### Типографика

- Текст — системный sans, как сейчас.
- **Всё числовое — моноширинным** (`--mono: ui-monospace, 'SF Mono', 'Cascadia Mono', Menlo, monospace`): значения параметров, единицы, оценки судьи, секунды этапов, остаток квоты, место в очереди. Это второй по силе носитель характера после сетки.
- Технические подписи (заголовки панелей, названия этапов) — в верхнем регистре, с межбуквенным интервалом `.04em`, размером 11 px, цветом `--muted`.

### Цвета предметов

Бейдж предмета в галерее и в карточке плана окрашивается **детерминированно по строке
предмета**: сумма кодов символов по модулю длины палитры. Закрытого списка предметов нет
и быть не может — их придумывает модель, поэтому сопоставление обязано работать для
любой строки. Палитра — шесть оттенков (циан, фиолетовый, янтарь, зелёный, розовый,
синий), каждый в виде пары «текст / подложка».

Одинаковый предмет всегда получает один цвет; это единственное требование к функции.

## 3. Примитивы

Сейчас primary-кнопка объявлена трижды: `.composer button.primary`
(`globals.css:183`), `.auth-card button.primary` (`:408`), `.empty-library button`
(`:359`) — при том что `.btn-primary` уже существует. То же с полями ввода. Перекраска
поверх такого расползётся.

**Требование:** после этой работы каждая кнопка в приложении — это `.btn` плюс
модификатор (`.btn-primary`, `.btn-secondary`, `.btn-ghost`, `.btn-danger`), каждое поле
ввода — `.input`, каждая карточка — `.card`. Дублирующие объявления удаляются, компоненты
переводятся на общие классы.

Это условие, а не украшение: без него следующая правка темы снова разъедется.

## 4. Экран входа

Сейчас: карточка по центру пустого экрана.

Становится: две колонки. Слева — та же форма. Справа — **живая витрина**: в `iframe`
крутится настоящая вшитая демка (маятник), поверх неё подпись, объясняющая, что это
такое. Человек видит продукт до того, как заведёт аккаунт.

Витрине нужен **публичный роут** `GET /api/showcase`, отдающий инструментированный HTML
вшитой демки из `demos/`. Это файл из репозитория, а не пользовательские данные, но это
единственное место работы, затрагивающее периметр доступа, поэтому:

- роут не обращается ни к базе, ни к хранилищу симуляций;
- он отдаёт ровно одну демку с фиксированным slug, без параметров запроса;
- `/api/showcase` добавляется в список публичных префиксов `src/middleware.ts`.

На узком экране (< 900 px) витрина скрывается, остаётся форма.

## 5. Мастерская

### Композер

- Поле ввода крупнее (не менее четырёх строк), с монопространственной подписью-заголовком.
- Под полем — **чипы-примеры**: шесть коротких промптов по разным предметам («диффузия духов в комнате», «маятник Фуко», «преломление луча в воде», «цикл Карно», «поле двух зарядов», «орбита спутника»). Нажатие подставляет текст в поле, не отправляя его.
- Режим качества — **сегментированный переключатель** из трёх кнопок вместо `<select>`. Видно все три варианта и выбранный, без раскрытия списка.
- Чипы и переключатель скрыты, когда открыта существующая симуляция (там режим доводки).

### Прогресс

Сейчас это горизонтальная россыпь чипов плюс карточки. Становится **вертикальной лентой
прибора**: этапы идут сверху вниз, у каждого — индикатор состояния, название и, для
активного, счётчик секунд моноширинным. Ниже ленты — план, живой скриншот (как только
пришёл), оценки судьи полосками, круги доводки.

Существующие компоненты (`StageTimeline`, `PlanCard`, `CandidateCard`, `RefinePanel`) и
`deriveProgress` сохраняются: меняется их оформление и раскладка, не логика. Событийная
модель не трогается вовсе — реплей после перезагрузки обязан продолжать работать.

### Превью

`PreviewFrame` получает рамку «экрана прибора»: тёмная подложка, тонкая граница, скруглённые
углы, подпись с названием симуляции сверху. Панель действий внизу приводится к общим кнопкам.

## 6. Галерея

Экран `/library` переименовывается в интерфейсе в «Галерею» (путь остаётся прежним).

### Панель фильтров

- Поиск (как сейчас, по названию, промпту, предмету и тегам).
- Предметы — чипами, построенными из фактически присутствующих в библиотеке предметов; выбранный чип фильтрует.
- Сортировка: по дате обновления (по умолчанию) и по названию.

Фильтрация и сортировка выполняются на клиенте над уже загруженным списком: серверный
поиск относится к другому циклу, здесь речь только об интерфейсе.

### Карточка

Превью 16:10, бейдж предмета цветом, название, теги, дата моноширинным, действия.

**Оживление при наведении.** Через 150 мс после наведения курсора карточка запрашивает
`GET /api/simulations/<id>` и монтирует настоящую симуляцию в `iframe` внутри превью;
при уходе курсора iframe размонтируется и возвращается статичный кадр. Ограничение:
**одновременно играет не более одной карточки** — новая наведённая останавливает
предыдущую.

На устройствах без наведения (`hover: none`) вместо этого показывается кнопка ▶ в углу
превью, включающая ту же симуляцию по нажатию; повторное нажатие останавливает.

Выбран этот путь, а не запись анимированных превью при генерации, потому что он не
требует серверной работы и **работает на всех уже сохранённых симуляциях без
перегенерации**.

### Пустое состояние

Крупная карточка по центру: одна фраза о том, что библиотека пуста, и кнопка «Установить
10 примеров» — вместо нынешней строки серого текста с кнопкой под ней.

## 7. Презентация

Сохраняется полноэкранный `iframe`. Кнопка «Выйти» заменяется **панелью, всплывающей при
движении мыши** и прячущейся через три секунды покоя: выход в галерею, полный экран,
возврат в мастерскую к этой симуляции. На касание панель показывается по тапу.

## 8. Онбординг

При первом входе поверх мастерской — три шага: «опишите явление словами», «мы соберём
интерактивную симуляцию», «покажите её классу». Пропускается кнопкой, факт прохождения
хранится в `localStorage`.

Онбординг реализуется **последним** и при нехватке времени срезается первым: он полезен,
но ни один другой пункт от него не зависит.

## 9. Тестирование

В проекте нет библиотеки для рендера React-компонентов в тестах, и вводить её ради этой
работы не будем. Отсюда правило: **вся логика, которую стоит охранять, выносится в чистые
функции и покрывается юнит-тестами**, а внешний вид проверяется живым прогоном.

Обязательно покрывается:

- цвет предмета: одинаковая строка даёт одинаковый цвет, разные строки распределяются по палитре, пустая строка не роняет функцию;
- фильтрация и сортировка галереи: чистая функция от списка и состояния фильтров;
- выбор карточки, которой разрешено играть: чистый редьюсер «какая карточка активна», включая правило «одновременно не более одной».

Существующие тесты (`derive-progress`, `step-copy`, `api`, интеграционные) обязаны
остаться зелёными: событийная модель прогресса и роуты не меняются.

Внешний вид проверяется контроллером вживую скриншотами на 1440×900 и 390×844 по каждому
экрану.

## 10. Критерии приёмки

1. Ни одно правило CSS не объявляет заново кнопку, поле ввода или карточку: в дереве остаётся ровно по одному определению `.btn`, `.input`, `.card`, а компоненты используют их.
2. Приложение тёмное на всех экранах, включая вход, галерею, мастерскую и состояния ошибок; фоновая сетка различима, но не мешает читать текст.
3. Все числовые значения на экране (оценки, секунды, остаток квоты, место в очереди, даты) набраны моноширинным шрифтом.
4. На экране входа без сессии видна и движется настоящая демка; `/api/showcase` доступен без сессии и не обращается к базе.
5. В композере видны шесть чипов-примеров; нажатие подставляет текст, не запуская генерацию. Режим качества — три видимые кнопки, выбранная выделена.
6. В галерее есть поиск, фильтр по предметам и сортировка; наведение на карточку запускает симуляцию, уход останавливает, одновременно играет не более одной.
7. На устройстве без наведения карточка показывает кнопку ▶, запускающую ту же симуляцию.
8. В режиме презентации панель появляется при движении мыши и скрывается через три секунды покоя.
9. `npm test`, `npx tsc --noEmit` и `npm run build` зелёные; интеграционные тесты с базой зелёные.
10. Реплей прогресса после перезагрузки страницы посреди генерации продолжает работать.
